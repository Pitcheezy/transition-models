# CV 개발 실행 환경과 협업 고지 판단 — 2026-10-26

사용자는 Claude Code 업데이트/한도 초기화 후 검토 재시도, 노트북과 원격 GPU의 효용, CV 계획의 협업 고지 여부를 물었다. 이 문서는 우리 연구 범위의 판단이며 자원 구매·원격 업로드·서비스 배포 승인이 아니다.

## 실제 조회

- Claude Code 전역 CLI2.1.310 (`claude --version`). 기존 임시2.1.251 대신 사용자 업데이트 버전으로 분할 검토를 재개했다. 실제 결과는 CV37 검토 기록을 따른다.
- CPU Intel Core i9-13900HX, 물리24/논리32; RAM31.7GiB.
- GPU RTX4070 Laptop, VRAM8188MiB. 조회 순간 사용295MiB·활용0%는 현재 순간값이며 CV 성능 측정이 아니다.
- 내부 NVMe WD PC SN810, 볼륨952.5GiB 중325.5GiB 여유, NTFS.
- 외장 Samsung T7 Shield USB, 볼륨3725.9GiB 중3723.1GiB 여유, exFAT. 외장 SSD 전송 속도와 지속 쓰기 성능은 미측정이다.
- 조회는 Win32_Processor/ComputerSystem, Get-Disk/Get-Volume, nvidia-smi였다. 파일 이동·포맷·전력/드라이버 변경은 하지 않았다.

## 지금은 노트북을 유지

[고정 CV37 첫 실측](CV_TRACKING_PILOT_20261026.md)에서 활성 추적 계산 중앙값은 CPU4.85ms, CUDA2.29ms였다. 첫 보고서의 전체625행 중앙값에는 초기화10행·대기492행이 섞여 있어, 그 수치로 활성 추적의 전체 속도를 판단하지 않는다.

Fable 지적 후 [v3 분리 보고서](results/cv_tracking_20261026/report_v3.json)에서 활성123회의 계산 중앙값은 CPU4.78ms·CUDA2.41ms, **읽기→결과 중앙값은12.82ms·11.23ms**였다(활성 추적의 읽기→결과 지연 중앙값 약12.4% 감소, 약1.14배). 전체 실행시간의 감소율이 아니다. 입력 디코딩과 CPU 우선 실행/캐시 영향이 포함된 개발 재생 한 번의 수치다. 대형 검출기 학습·온라인 서비스 지연·원격 GPU 효과를 측정한 것이 아니다. 현재는 추적 유지 중앙값0.551초라는 품질 문제를 먼저 해결한다.

현 단계는 원격 GPU를 구입하기보다 다음을 순서대로 측정하는 것이 낫다.

1. 동일 입력은 한 번만 검증/디코딩한 유한 캐시를 재사용한다. 원본 SHA와 PTS를 보존하며 미래 프레임을 판단 입력으로 섞지 않는다.
2. CPU 입력 준비와 GPU 추적 계산을 분리하고, 작은 영역만 처리한다. CPU 스레드/병렬 읽기 수는 늘리기 전에 비교 측정한다.
3. AI 판독은 초기 식별·실패 사례 확인에 한정하는 후보를 검토한다. 현재는 새 AI 영상 판독이나 재학습을 실행한 것이 아니다.
4. GPU 메모리 부족이 실제 발생하거나 새 모델 학습/다경기 처리가 목표 시간을 넘을 때, 같은 소형 작업을 원격 GPU에서 비교한다. 업로드·환경 재구성·결과 회수까지의 총 시간을 잰다.

Claude Code의 모델 검토는 원격 모델 호출이다. 노트북 GPU나 Colab으로 실행 위치를 옮기는 것으로 Claude 계정의 사용 한도를 늘릴 수는 없다. CV 픽셀 처리와 AI 코딩/검토 호출의 병목을 구분한다.

## 외장 SSD의 역할

코드·가상환경·현재 처리할 작은 프레임 묶음/캐시는 내부 NVMe에 두고, 외장 SSD는 큰 원본 영상·완료된 묶음·복구용 사본에 쓰는 구성을 우선 제안한다. 내부 여유325.5GiB가 있어 지금 즉시 옮겨야 할 상황은 아니다. 저장 위치만 바꾸어 추론이 빨라진다고 주장하지 않는다. 새 이동/복사는 목적지를 명시하고 SHA를 대조한 뒤 수행하며, 현재 원본은 그대로 둔다. 외장 한 개에만 두는 것은 별도 복구 사본이 아니다.

## Colab 또는 원격 서버를 쓸 조건

[Colab 공식 FAQ](https://research.google.com/colaboratory/faq.html)는 GPU 종류·가용성·사용 제한이 변하고 VM에 수명 제한이 있다고 설명한다. 저장 자료는 별도로 전달/회수해야 하므로, 재현 환경과 비공개 영상 관리도 준비해야 한다. 따라서 현재의 소규모 반복 개발/브라우저 검수는 노트북이 적합하고, 큰 GPU 메모리가 필요한 특정 학습/일괄 처리만 조건부 원격 후보로 둔다. Colab·다른 GPU의 실제 비교 속도/총비용은 미측정이며 가입·업로드를 실행하지 않았다.

## 협업 고지는 짧게

[협업 규약](COLLABORATION_PROTOCOL.md)에 따라 미트/영상 연구의 상세 계획·실험·실패·단축 일정은 우리 board에서 관리한다. 기존 계획은 [착수 글](https://github.com/Pitcheezy/transition-models/issues/3#issuecomment-6401534435)에 이미 기록돼 있다.

Song에게는 11/24 전시 목표,11/15 연구 기능 동결 목표, 기존 운영/공개 파일 계약/상대 일정에 변화가 없음을 한 번 알리는 것이 좋다. 연구 개시 승인을 받을 일은 아니며 현재 새 답변을 요구할 필요도 없다. 이미 받은 미트 자료 요청의 진행 공유는 우리 mail #18에 이어 남길 수 있고, 상대의 새 작업/계약 변경이 필요하면 상대 mail로 별도 요청한다. 공개 파일 계약의 항목 추가는 사전 고지, 삭제/의미 변경은 Song 승인 후 v2 원칙을 유지한다. 현재 사용자의 질문은 의견 요청이므로 상대 발신을 수행하지 않았다.
