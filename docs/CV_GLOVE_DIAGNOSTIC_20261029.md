# CV49b — 같은 3장의 기존 장갑 검출기 진단

## 실행 전 고정

기준 `ef35d191ddef277bbc2665e2f9373a2f723d9371`, 초안 PR84(PR83 위), main·배포와 별개다.
[착수 합격 기준](https://github.com/Pitcheezy/transition-models/issues/3#issuecomment-6486957342).
이 실험은 CV49a에서 두 AI가 서로 다른 물체를 같은 미트로 지목한 문제를 기존 검출기가 해결하는지
살펴보는 **개발용 후보 진단**이다. 사람 정답·독립 평가·포수 의도 정확도를 측정하지 않는다.

- 대상은 CV49a의 `849843:1:1`, `849843:1:2`, `849843:1:3` 대표 PNG 그대로다.
- 원본 1280×720와 기존 포수 문맥 crop `[450,240,660,470]`를 각 한 번 입력한다.
  총 6조건이지만 독립 프레임은 3장이다. PTS·원본 영상/이미지 SHA는 CV49a manifest에 고정돼 있다.
- 모델은 `fasterrcnn_mobilenet_v3_large_fpn` / COCO V1 / `baseball glove`(40)이다.
  선택 근거는 새 결과가 아닌 기존 [observer 사전 계획](results/cv_local_20261007/observer_preregister_v1.json)이다.
- 기본 threshold 0.5, CUDA, threads 4, batch 1, load 1회, warmup 0, 재시도 0, 추가 학습 0.
  SSDlite도 로컬 파일 존재·전체 해시는 확인하지만 이번 6조건 추론에는 사용하지 않는다.
- 기존 benchmark는 JPEG만 받아 원본 PNG를 바꾸게 되므로 사용하지 않는다. 기존 검출 엔진을
  직접 호출하는 작은 실행기를 사용한다. 크롭 결과는 엔진이 이미 원본 좌표로 투영하므로 다시 더하지 않는다.
- 추론 전 가중치·실행기·검출기·입력검사·입력 manifest·이미지·두 AI 응답 해시를 고정한다.
  추론 과정은 AI 응답을 읽지 않는다. 모든 후보·무후보·복수 후보·오류를 저장한 뒤 비교한다.
- 검출 상자를 각 AI의 각 객체 상자와 따로 대조한다. 가까운 상자를 골라 정답으로 삼지 않는다.
  미해결 AI 객체의 겹침은 비교 불가이며 0으로 바꾸지 않는다. IoU는 기하학적 겹침뿐이다.
- 검출 점수는 정확도나 보정된 확률이 아니다. 상자 중심은 검증된 미트 중심·목표가 아니다.
  단일 glove도 포수 소유라는 보장이 없다. 기존 일반 검출기의 서비스 부적합 결론을 자동 뒤집지 않는다.

## 기존 환경·가중치 확인

기본 모델 환경에는 torch만 있고 torchvision이 없었다. 기존 intent 작업의 별도 가상환경에서
호환 torch/torchvision와 CUDA를 실제 import해 확인했다. 새 설치·다운로드·환경 수정은 없다.
가중치 두 파일의 원본 바이트 SHA와 크기가 10/7 고정 기록과 일치한다.
기기 절대 경로는 비공개 실행 영수증에만 둔다.

| 기존 가중치 | 바이트 | SHA-256 |
| --- | ---: | --- |
| Faster R-CNN | 77,844,807 | `fb6a3cc702b1df54c18a44b26708cd083614211062d0c36d2ca7bf9270df3533` |
| SSDlite | 14,069,355 | `a79551df90c79834bcd3bb3845ef9d966b5449a3a9b2833ae8404778ca5d65d2` |

실제 재사용 환경은 Python3.12.12 / torch2.6.0+cu124 / torchvision0.21.0+cu124 /
Pillow12.2.0 / RTX4070 Laptop GPU다. 기본 환경과 별도 환경을 혼동하지 않는다.

총18개는 엔진이 반환한 임계값 미만 glove 상자이며 모델 내부의 모든 제안을 뜻하지 않는다.
여섯 조건 모두 `no_candidate`다. **이 세 프레임에서는 기존 검출기를 미트 점 생성기로 채택하지 않는다.**
3개 프레임을 두 조건에서 본 진단이며 정확도0%나 전체 경기 검출률0%를 뜻하지 않는다.

포수 크롭의 일부 낮은 점수 상자는 기존 AI의 보호대 지목과 겹쳤다. 예를 들어 2구 D17은
Codex의 보호대 상자와 IoU0.9396이다. 이는 기하학적 비교이며 사람 정답으로 확인한 오검출이 아니다.
상자 점수를 낮춰 채택하거나 AI끼리 겹친다는 이유로 정답을 만들지 않는다. 두 AI 모두 맨손 지목은
미해결이므로 맨손 IoU는 `null`이다. 어느 AI의 미트 지목이 맞는지도 이번 결과로 확정하지 못했다.

GPU 모델 호출 시간은 첫 호출1.529초, 나머지0.0208~0.0795초였다. warmup 없는 단6회이고
시작·디코딩·화면 전송 등을 포함한 서비스 지연이 아니므로 실시간 처리 성능으로 주장하지 않는다.

## 재현과 비공개 비교 화면

실행기는 원본 PNG를 재인코딩하지 않고 기존 엔진에 바이트와 SHA를 넘긴다.
비교기는 **추론 종료 후** 고정된 두 AI 원응답을 읽어 모든 검출 상자의 객체별 IoU를 남긴다.
화면에서 A는 Codex의 기존 지목(청록), B는 Claude Fable의 기존 지목(자홍)이다.
검출 상자는 점수0.5 이상 노랑·미만 회색이다.
같은3장×두조건 나란히 보기와 포수 크롭 확대, 원점수·원본 float 좌표를 보존한다.
비공개 이미지·원문·기기 경로·실행 결과는 `outputs/cv49b_*`에만 있다.

```sh
# 이전 모델 실행 환경의 Python 사용. <WEIGHTS>는 위 SHA와 같은 기존 파일.
python scripts/80_diagnose_glove_candidates.py \
  --plan docs/results/exhibition_replay_20261028/detector_plan_v1.json \
  --input outputs/cv49a_object_reference_20261028_v1/input.json \
  --weights <WEIGHTS> --output outputs/cv49b_new_run
python scripts/81_compare_glove_candidates.py \
  --plan docs/results/exhibition_replay_20261028/detector_plan_v1.json \
  --input outputs/cv49a_object_reference_20261028_v1/input.json \
  --run outputs/cv49b_new_run/result.json \
  --reading-a outputs/cv49a_object_reference_20261028_v1/codex_reading.json \
  --reading-b outputs/cv49a_object_reference_20261028_v1/claude_reading.json \
  --out outputs/cv49b_new_comparison
```

새 실행은 필요할 때만 한다. 코드·입력의 줄바꿈을 포함한 바이트가 고정 SHA와 다르면 거부한다.
다른 체크아웃에서는 고정 커밋의 바이트와 원본 파일을 먼저 대조하며 검사 우회·무조건 재고정하지 않는다.
비교 화면 생성은 저장된 결과로 재현할 수 있어 GPU 재추론이 필요 없다.

## 교차검토와 다음 단계

Claude Fable의 실행기 검토는 approve이며, 손상 PNG의 오류 코드·실패 메시지·경로 표기 세 가지
낮은 우선순위 보완을 남겼다. 이번 입력·실행 결과에는 영향이 없고 고정 실행본을 바꾸지 않았다.
비교기 검토에서 크롭 상자를 전체 화면 범위만 검사하는 문제가 발견됐다. 추가 회귀는 수정 전17실패,
수정 후 통과했다. `f27576a070b8669c88dfede6369b8a9df203fdfa`에서 크롭 범위·고정 환경/가중치·
필수 해시 검사와 확대 표시를 보완했다. 저장 결과만으로 만든 최종 화면은 `outputs/cv49b_comparison_20261029_v2/index.html`이다.
추론 원문과 비교v1도 보존했다. Python 관련161검사·Chrome155의 3카드/6조건/원본6삽입·외부요청0·
페이지오류0 확인, 최종 확대6장 직접 확인. 스크롤 밖 영역 캡처의 첫 실패는 별도 SVG 뷰포트 렌더로 해결했으며
브라우저 검사이지 실제 Mac 사용 검사가 아니다.

Fable 최종 비교기 검토와 결과 수치 해석 검토는 approve다. 결과 검토는 이미지 판독이 아니라 JSON 수치 검토다.
최종 검토의 해시중복 횟수 지적은 실행기가 각 파일마다 체크를 남기므로 해당하지 않는다. 실제9개 체크가 일치한다.
비교기는 신뢰된 로컬 실행기의 해시 기록을 대조하며 가중치 출처를 별도로 인증하는 도구가 아니다.
HTML 브라우저용 SVG를 엄격한 독립 XML 파일로 보장하지 않으며, 일부 메타데이터의 bool/int 동일값 수용은
낮은 우선순위 후속 보완으로 남겼다. 실제 이번 응답 필드 타입은 원래 엔진의 정상 타입이다.
[결과·검토 영수증](results/exhibition_replay_20261028/detector_diagnostic_v1.json)에 실제 모델·검토범위·해시를 기록한다.

이번 진단은 객체 식별 문제의 해결이 아니다. 다음 후보 작업은 같은 개발 자료에서 **포수의 팔·양손·장비
관계와 시간에 따른 연결을 근거로 미트/보호대를 구분할 수 있는지** 작은 범위에서 검사하는 것이다.
추적 지속시간이나 낮은 검출 점수를 식별 근거로 대신하지 않는다. 정확한 후속 단위는 CHECKLIST에서 관리한다.
기존 v3·2구 기권·사람 응답·평가 잠금849844·팀원 저장소·Cloudflare는 변경하지 않았다.
