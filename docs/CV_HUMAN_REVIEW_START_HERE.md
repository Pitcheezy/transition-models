## 실제 순서

1. 새 `outputs/cv_review_20261008_ui_v3/reviewer/` 팩의 실행 도우미를 켠다.
   아래 명령을 실행한 **같은 컴퓨터**에서 도우미가 표시한 주소를 연다.
2. **검토자 ID**에 본인이 구별할 수 있는 별칭을 입력한다. 예: `reviewer_A`.
   같은 사람이 이어서 할 때는 같은 ID를 쓰고, 두 번째 사람은 다른 ID를 쓴다.
3. 미트 중심을 읽을 수 있으면 이미지에서 **한 번 클릭**한다. 상태는 자동으로 ‘중심을 표시함’이 된다.
   잘못 찍었다면 정확하다고 판단한 곳을 다시 클릭한다. 실제 좌표는 원본 픽셀 기준으로 기록된다.
4. **미트 가시성**을 직접 선택하고, **자세**를 별도로 고른다. 아래 표를 참고한다.
   일부가 가려진 경우에는 왜 중심을 읽을 수 있다고 판단했는지 이유를 적는다.
5. 중심을 읽을 수 없으면 상태를 ‘중심을 읽을 수 없음’으로 바꾸고 이유를 적는다.
   판독 가능 여부 자체가 애매하면 ‘판단이 불확실함’으로 두고 이유를 적는다. 억지로 점을 찍지 않는다.
6. **다음**으로 이동한다. 다 보지 못한 이미지는 ‘아직 검토하지 않음’으로 남겨도 된다.
7. 중간에 멈추거나 아직 선택하지 않은 값이 있으면 **작업 초안 저장 · 제출용 아님**을 누른다.
   내려받은 초안 파일이 실제 있는지 확인한다. 초안은 제출하지 않는다.
8. 제출할 내용을 확인한 뒤 **제출용 응답 JSON 내보내기**를 누른다. 상태·좌표·가시성·필수 이유는
   기존의 엄격한 검사를 통과해야 한다. 오류가 나오면 표시된 프레임에서 사람이 입력을 보완한다.
9. 내보낸 최종 응답 JSON을 이 채팅에 첨부한다. 원본은 보관한다. Codex가 구조와 자료 결속을 검사하고 집계한다.

## 선택지 뜻

| 구분 | 화면 선택지 | 선택하는 경우 |
|---|---|---|
| 상태 | 중심을 표시함 | 중심을 특정할 근거가 있어 클릭했다. 가시성은 전체/일부 중 하나여야 한다. |
| 상태 | 중심을 읽을 수 없음 | 가림·흐림 등으로 중심을 특정할 수 없다. 점은 지워진다. |
| 상태 | 판단이 불확실함 | 판독 가능 여부나 무엇이 미트인지 확신하기 어렵다. 점은 지워진다. |
| 상태 | 아직 검토하지 않음 | 아직 읽지 않았거나 해당 행을 초기화한다. 기존 점과 판정이 지워진다. |
| 가시성 | 전체가 보임 | 미트 몸체를 읽을 수 있을 만큼 전체가 보인다. |
| 가시성 | 일부가 가려짐 | 일부는 가려졌지만 보이는 외곽으로 중심을 읽을 근거가 있다. 이유 필수. |
| 가시성 | 가려져 보이지 않음 | 미트가 가려진 경우다. 중심 표시와 함께 쓸 수 없다. |
| 가시성 | 확신 없음 / 아직 선택 안 함 | 가시성을 확정하지 못했다. 중심을 표시한 행은 전체/일부로 직접 선택해야 한다. |
| 자세 | 공을 받기 위해 제시한 자세로 보임 | 화면의 자세를 그렇게 관찰한 것일 뿐 투수의 의도를 확인했다는 뜻은 아니다. |
| 자세 | 내려놓거나 쉬는 자세로 보임 | 낮게 내려놓거나 쉬는 모습이다. 그래도 중심이 보이면 표시한다. |
| 자세 | 움직이는 자세로 보임 | 움직이는 모습으로 판단할 근거가 있다. 한 장만 보고 알기 어렵다면 확신 없음으로 둔다. |
| 자세 | 확신 없음 | 자세를 구분할 근거가 부족하다. 이 선택 자체는 중심 표시를 막지 않는다. |

이유는 자기 눈으로 본 내용을 짧게 적으면 된다. 가상의 예: “일부가 무릎에 가렸지만 보이는 몸체로 중심을 읽음”,
“가려져 중심을 특정할 수 없음”, “미트인지 팔인지 구별하기 어려움”. 실제 이미지에 없는 이유를 복사하지 않는다.
플레이트 좌표나 발·무릎을 추가로 표시할 필요는 없다.

## 중단했다 이어서 하기

닫기 전에 **작업 초안 저장 · 제출용 아님**을 눌러 다운로드 폴더에서 파일을 확인한다. 다음에 같은 팩을 열고
**저장한 응답 / 초안 불러오기**로 그 파일을 선택하면 빠진 선택지와 작성 중인 이유까지 이어서 볼 수 있다.
초안 저장이 미완성 값을 자동으로 채우거나 최종 응답으로 바꾸지는 않는다.

이미 **제출용 응답 JSON 내보내기**로 저장한 응답도 같은 **저장한 응답 / 초안 불러오기**로 연다.
이 입력칸은 최종 응답과 초안을 구분해 불러온다. 초안을 불러와도 제출용 응답으로 바뀌지는 않는다.
초안은 제출 검사에서 받지 않으며, 다른 팩의 파일도 사용하지 않는다.
현재 화면에 저장하지 않은 입력이 있으면 교체 전에 먼저 초안을 저장한다.
기본 다운로드 이름은 초안 `human_review_draft.json`, 최종 응답 `human_review_response.json`이다.
이전 파일은 덮어쓰지 말고 초안/완료본을 별도 이름으로 보관한다. 브라우저를 닫기만 해서는 저장되지 않는다.

2026-10-08 이전 UI에서 일부 가림을 선택하고 이유 없이 내보낸 파일은 새 검사에서 거절될 수 있다.
원본 파일은 보존하고 해당 이미지를 실제 사람이 다시 확인해 이유를 보완한다. 이유를 AI가 대신 작성하지 않는다.

## 팀원의 도움이 필요한 시점

본인의 첫 검토는 단일 검토자 개발 자료로 쓸 수 있다. 그것만으로 독립 정확도나 사람 간 일치도를 발표하지 않는다.
**가용성 합의 평가에는 최소 두 사람의 판단을 먼저 각각 저장**하고, 다른 부분은 이후 별도로 판정한다.
두 번째 사람은 동선님일 필요가 없다. 규약을 읽고 이전 점·첫 사람의 응답을 보지 않고 검토할 사람이면 된다.
현재 개발에 관여한 사람이 다시 읽는 것과 최종 독립 평가자는 구분한다.

CV7 최종 독립 평가는 개발자가 보지 않은 새 영상과 이번 개선·AI 출력에 관여하지 않은 새 라벨러가 필요하다.
이번26장 재검토를 팀원에게 맡기더라도 이미 사용한 두 경기가 새 독립 평가 자료가 되지는 않는다.

도움받는 사람에게는 `start_review.py`를 포함한 새 `reviewer/` 폴더 전체만 비공개로 전달한다.
HTML만 따로 보내지 않는다. 상위 `private_selection.json`, 이전 좌표나 비교 그림은 함께 주지 않는다.
원본 중계 화면을 공개 웹·공개 저장소에 올리지 않는다.

## 검토 화면 켜기

Python 3가 설치된 컴퓨터에서 받은 `reviewer/` 폴더를 터미널로 연다.
먼저 자료를 검사하고, 성공하면 같은 도우미로 화면을 켠다. 검사는 사람의 판독 정확도를 평가하지 않는다.

Mac:

```text
python3 start_review.py --check
python3 start_review.py --open
```

Windows:

```text
py -3 start_review.py --check
py -3 start_review.py --open
```

기존 Windows 저장소 환경에서는 저장소 루트에서 다음 명령으로 실행할 수도 있다.

```text
.\.venv\Scripts\python.exe outputs/cv_review_20261008_ui_v3/reviewer/start_review.py --check
.\.venv\Scripts\python.exe outputs/cv_review_20261008_ui_v3/reviewer/start_review.py --open
```

`--check`는 검사만 하고 서버를 켜지 않는다. `--open` 없이 실행하면 표시된 주소를 직접 연다.
포트는 기본값 `0`으로 빈 번호를 자동 선택하므로 화면을 다시 켤 때 주소가 달라질 수 있다.
직접 `--port`를 지정했다가 이미 사용 중이라는 안내가 나오면 그 옵션을 빼고 다시 실행한다.

**주소는 이 명령이 실행 중인 컴퓨터에서만 연다.** Mac 브라우저에 Windows의 주소를 복사하면
같은 서버에 연결되지 않는다. Mac으로 팩을 옮겨 위 Mac 명령을 실행하거나 Windows의 화면을 사용한다.
도우미는 외부 공개나 다른 컴퓨터에서 접속하기 위한 네트워크 설정을 자동으로 하지 않는다.
사용 중에는 터미널을 켜 두고, 끝나면 `Ctrl+C`로 종료한다. 화면이 꺼지면 다시 실행한다.
서버 재실행으로 입력이 복구되지는 않으므로 저장한 초안이나 최종 응답을 직접 불러온다.
