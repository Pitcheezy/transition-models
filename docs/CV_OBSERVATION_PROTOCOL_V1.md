# 미트 관측 v1 — 다음 개발과 독립 평가 규약

작성일: 2026-10-05. 상태: **개발 규약과 평가 준비안**. 새 영상·라벨러·실행 버전·평가 표본은 아직 확정하지 않았으며, 이 문서 작성만으로 독립 평가를 시작하거나 완료한 것으로 보지 않는다.

본인 담당 범위는 영상 관측, 투구 연결 근거, 좌표 변환, 기권과 품질 평가다. 팀원의 확률·추천 모델, 경기 피드 수신, 관전 화면과 서비스는 수정하지 않는다. 기존 M3 보고서와 10/6 시연 JSONL도 변경하지 않는다.

## 1. 이번 버전에서 관측하는 대상

**관측값은 해당 프레임에서 보이는 포수 미트 몸체의 영상상 중심이다.** 미트가 땅에 내려가 있거나 휴식 자세에 있어도 중심을 판독할 수 있으면 표시한다. 이는 포수가 투수에게 제시한 목표인지, 투수의 의도인지와 별개다.

| 항목 | v1 규칙 |
|---|---|
| 위치 | 원본 전체 프레임의 픽셀 좌표. x는 이미지 오른쪽, y는 아래쪽이다. 확대·crop 좌표는 원본으로 환산한다. |
| 중심 | 미트 몸체 외곽의 좌우·상하 중간을 기준으로 읽는다. 손목끈, 팔, 공의 중심을 대신 찍지 않는다. |
| resting 미트 | 보이면 표시한다. `resting` 여부는 별도 관찰 속성이며 기권 조건으로 사용하지 않는다. |
| 부분 가림 | 중심을 판독할 근거가 충분하면 `partial`로 표시하고 이유를 남긴다. 위치를 특정하기 어렵다면 기권한다. 보이지 않는 외곽을 억지로 복원하지 않는다. |
| 셋업 의미 | `presented_target`, `resting`, `moving`, `unknown`을 위치 표시와 분리해 기록한다. 프레임만으로 구별하기 어렵다면 `unknown`이다. |
| 투수 의도 | 판단하지 않는다. 미트 관측을 투수의 목표 위치나 의도 정답으로 사용하지 않는다. |
| 좌표 변환 | 미트 픽셀은 보이지만 플레이트·보정 정보가 없으면 픽셀 단계까지만 출력한다. x 피트 좌표의 결측과 미트 자체의 결측을 구분한다. |

이 정의는 다음 판독 버전용이다. 기존 `IntentEstimate v1`의 필드·의미를 조용히 변경하지 않는다. resting 등의 추가 판정은 우선 별도 개발 기록에 두고, 서비스 계약 변경이 필요하면 독립된 버전과 합의로 처리한다. 기존 `is_intent_proxy`, 미검증 주장 필드는 유지하며 관측이 곧 의도라는 설명을 추가하지 않는다.

[기존 M3 기록](INTENT_V0_M3_EVAL.md)에는 AI 기권 28장, 사람 기권 2장과 판독 지시의 차이가 남아 있다. **대상 정의 차이가 일부 기권 차이를 설명할 수 있다는 것은 가설**이다. 26장의 사람 단독 표시를 전부 AI 오류나 불필요한 기권으로 확정하지 않는다. 새 규약 아래에서 원인을 별도로 재검토해야 한다.

## 2. 두 평가를 구분한다

### A. 정해진 프레임에서의 관측 평가

고정 프레임의 미트 중심을 읽는 능력과 기권 판단을 평가한다. 어떤 방식으로 그 프레임을 선택했는지 출처를 기록한다. 릴리스 이후를 보고 프레임을 고른 경우에는 **사후 프레임 선택 조건의 관측 평가**라고 쓴다. 프레임 판독이 좋아도 실시간 투구 전 제공이 입증되는 것은 아니다.

기존 M3는 이 계열의 결과로 보존한다. 기존 출력에 새 resting 규칙을 소급 적용하거나 기존 결과를 새로운 독립 평가로 이름만 바꾸지 않는다.

### B. 투구 전 시간순 처리 평가

목표는 시점 t까지 실제로 확보된 영상·정보만으로 결과를 내는 것이다. 프레임의 재생 시각이 릴리스보다 이르다는 사실만으로 통과시키지 않는다. **자료 도착, 처리 완료, 출력 발행 시점까지 측정**한다.

- 처리기에 시점 t 이후 프레임·구종/구속 그래픽·투구 결과·최종 feed를 제공하지 않는다.
- “릴리스 직전 마지막 프레임”을 뒤에서 골라 주지 않는다. 다음 프레임을 보아야 확인되는 조건은 출력 시점에 사용할 수 없다.
- 관측 프레임 선택·기권·현재 투구 식별·보정 갱신은 모두 동일한 시점 제한을 적용한다.
- roll, 폭, 카메라 파라미터는 t 이전 prefix 또는 해당 실행 전에 독립적으로 확보한 스냅샷만 사용한다. 같은 타석·경기 전체 중앙값은 허용하지 않는다.
- 보정 스냅샷에는 사용 프레임·파일 해시, 원본 시각, 실제 확보 시각, 생성 완료 시각을 기록한다. 확보 시점이 불명확하면 해당 결과의 투구 전 가용성은 `unknown`이다.
- 최종 pitch_id와 릴리스 시각은 평가자가 사후에 연결할 수 있지만 처리기의 입력으로 되돌려 주지 않는다. 실시간 키가 미확정이면 임시 관측 ID와 연결 상태를 보존한다.
- 릴리스 기준 시각은 별도 정답 작성자가 확인한다. 처리기는 그 정답을 보지 않는다. 시각 정답이 불명확한 건은 별도 결측으로 보고한다.
- 영상 재생 시계와 단조 증가하는 처리 시계를 구분해 기록한다. 결과가 준비된 시점과 릴리스 기준 시점의 차이로 여유 시간·지연을 산출한다. 방송 신호 자체의 지연을 모르면 실제 경기 현장의 시간 기준 성능은 주장하지 않는다.
- 로컬 시간순 재생은 재생 실험이다. 실제 중계 수신부터 출력까지 측정하지 않았다면 “실시간 중계 전체 처리 지연”이라고 부르지 않는다.

현재 코드의 사후 의존성은 [압축 경기 연결](../intent/condensed.py), [판독 프롬프트](../intent/workflows/condensed_read.js), [pooled 보정 사용](../intent/run.py), [카메라 보정](../intent/calibrate.py)을 기준으로 점검한다. 단계 하나의 prefix 분석을 전체 파이프라인 투구 전 성공으로 해석하지 않는다.

## 3. 개발·검증 영상과 사람 검토

- **747139, 849843, 849845, 823407은 이후 개선에서는 모두 개발 자료다.** 원래 M3에서의 경기 역할과 당시 결과는 그대로 보존한다.
- 이미 판독·처리한 보충 경기 849849도 새 영상으로 간주하지 않는다. 다른 영상은 프레임 열람·AI 판독·개발 사용 이력을 확인한 뒤 역할을 정한다.
- 독립 평가에는 개발자가 아직 보지 않은 영상과 이번 개선·AI 출력에 관여하지 않은 새 라벨러가 필요하다. 같은 경기의 다른 프레임을 새 독립 경기로 세지 않는다.
- 평가 영상은 경기 ID·방송사·길이 등 내용 외 메타데이터와 사전 선정 규칙으로 선택한다. 프레임이나 모델 결과를 보고 잘 나오는 경기로 교체하지 않는다.
- 압축 영상은 편집자가 선택한 투구 표본이다. 결과를 전체 투구 또는 모든 중계 상황으로 확대하지 않는다. 투구 전 평가에는 관측 시작 구간이 있는 연속 영상이 필요하며, 확보되지 않으면 영상 확보 대기로 남긴다.
- 새 사람 검토자는 AI 좌표·기권 여부·투구 결과를 보지 않은 상태에서 동일 규약을 읽고 라벨한다. 연습은 개발 자료로만 하고 평가 자료를 연습에 사용하지 않는다.
- 가용성은 최소 두 사람의 독립 판단을 먼저 보존한 뒤, 불일치 건을 별도 절차로 판정한다. 합의가 안 되면 `unknown`을 유지한다. 이 조건을 채우지 못하면 단일 라벨러 비교로 보고한다.
- 독립 판단과 최종 판정은 다른 파일에 보관한다. 토론 후 합의값으로 원래 판단을 덮어쓰지 않는다. AI끼리의 교차 확인을 사람 간 일치도로 보고하지 않는다.

## 4. 실행 전에 고정할 내용

새 평가 프레임을 열기 전에 다음 항목을 실행 manifest와 커밋으로 고정한다. 비어 있는 항목이 있으면 평가 준비 상태다.

1. 이 규약의 버전·커밋·sha256, 사용 코드·프롬프트·모델 및 도구 버전.
2. 개발/평가 경기·영상 ID, 영상 종류, 선정·보충·제외 규칙, 표본 수 또는 종료 규칙.
3. A/B 중 평가 유형, crop·프레임 선택 규칙, 출력 채택·기권 기준, 재실행 정책.
4. 미트 중심·부분 가림·resting 지시와 라벨 UI 버전, 독립 라벨러 식별자와 가림 정보.
5. 플레이트 앞선·좌우·단위 정의, 보정 방법과 허용되는 정보 시점.
6. 아래 지표별 분모·집계 방식과 결측 처리. 정확도 숫자를 본 뒤 유리한 분모로 바꾸지 않는다.
7. 실행 장비, 병렬도, 시계·지연 기록 방법, 시간순 실험의 입력 도착 일정과 출력 마감 기준.
8. 프로그램 실패 재시도 횟수·조건. 같은 입력/버전 재시도인지, 새 개발 버전인지 구분한다.

방법을 바꾸면 새 버전을 발급하고 변경 이유를 기록한다. 이미 열람한 평가 자료는 그 수정 버전의 개발 자료가 된다. 물리 정확도 목표나 임의의 합격 오차를 이 문서에서 만들어 넣지 않는다. 사용자 요구에 따른 합격 기준이 필요하면 근거와 함께 평가 전에 별도로 정한다.

## 5. 반드시 남길 출처

- 영상 식별자·로컬 파일 SHA·frame index·원본 frame SHA·frame time·fps 및 추출 명령.
- pitch_id 또는 임시 관측 ID, 연결 근거와 연결 완료 시점. 행 순서로 연결하지 않는다.
- points, JSONL, 라벨 팩, 원본 사람 라벨, 보정 파일의 경로·SHA·버전·생성 시점.
- 처리기 입력 제공 범위, 사용한 외부 정보와 확보 시점, 출력 발행 시점.
- 사람 라벨러·라벨 출처·독립 작업 여부·판정 이유·변경 이력.
- 성공·기권·오류·중단·재시도 결과 전체. 마지막 성공본만 남기지 않는다.

이미지·영상은 기존 비공개 로컬 검토 범위를 따른다. 평가 결과 공유를 위해 원본 중계 화면을 공개 저장소에 추가하지 않는다. 저장된 SHA 일치 검사와 원본 이미지 바이트 재검증의 수행 여부도 구별한다.

## 6. 지표와 분모

경기별 결과를 기본으로 낸다. 개발·독립 평가 결과를 합산하지 않는다. 독립 경기 합산이 필요하면 경기별 수와 원래 영상 표본의 편향을 함께 제시한다.

| 지표 | 분자·분모와 해석 |
|---|---|
| 원본 포함률 | 선택된 투구 / 원본 경기 전체 투구. 사후 feed는 분모를 세는 평가자에게만 허용한다. 압축 편집으로 빠진 투구를 성공으로 세지 않는다. |
| 처리 도달률 | 처리기가 판단까지 완료한 투구 / 사전에 정한 평가 대상 전체. 오류·중단·기권을 모두 따로 센다. |
| 픽셀 출력률 | 미트 픽셀을 출력한 투구 / 평가 대상 전체. 정답·오답과 별개의 출력 범위다. |
| x 좌표 출력률 | x 피트까지 도달한 투구 / 평가 대상 전체. 픽셀만 가능한 투구와 분리한다. |
| 투구 전 가용률(B) | 릴리스 전에 결과가 실제 발행된 투구 / 사전 정의한 대상 전체. 늦은 출력·시간 미측정·투구 연결 미확정도 별도로 센다. 미측정은 성공이나 0초로 대체하지 않는다. |
| 조건부 위치 차이 | AI 출력과 사람 기준점이 모두 있고 프레임이 일치한 투구만 대상으로 픽셀 거리·x/y 차이를 보고한다. 중앙값·90분위·n을 함께 제시하고 전체 정확도로 부르지 않는다. |
| x 변환 차이 | 같은 변환을 쓴 판독 차이, 각자 앞선을 쓴 출력 차이, 변환 파라미터 민감도를 분리한다. 공통 변환의 결과 차이는 물리 오차 검증이 아니다. |
| 잘못된 출력 | 합의된 기준에서 중심 판독 불가인데 AI가 좌표를 낸 투구. `판독 불가 중 출력 수 / 판정된 판독 불가 수`와 `출력 중 해당 수 / 판정 가능한 전체 출력 수`를 각각 표시한다. |
| 기권 적절성 | AI 기권 중 사람이 동일 규약으로 판독 불가라고 판정한 비율. 별도로 판독 가능인데 기권한 수를 제시한다. 단독 사람 표시만으로 AI 기권이 틀렸다고 확정하지 않는다. |
| 미확정 판단 | 사람 미판정·불일치 미해결·프레임 연결 불명·원본 손상 수를 전체 분모와 함께 공개한다. 해당 건을 오답률 계산에서 제외했다면 제외 수를 명시한다. |
| 처리 시간·비용 | 읽기·프레임 처리·판독·보정·출력 및 재시도 시간을 구분한다. 수동 대기와 외부 서비스 사용량도 별도 기록하며 subprocess 시간만으로 전체 지연을 주장하지 않는다. |

가용성 표에는 `둘 다 표시`, `둘 다 기권`, `AI만 표시`, `사람만 표시`, `사람 미판정`, `평가팩 미포함`을 남긴다. 사유를 알 수 없으면 `unknown`으로 기록한다. 모든 false output·기권 적절성 지표는 **동일한 목표 정의로 사람 판정이 끝난 범위**에서만 계산한다. 분모가 0이면 수치는 `null`이다.

## 7. 중단·무효 처리 조건

- ID 중복·프레임 SHA/시각 불일치·다른 경기 파일·비유한 좌표·변환 불일치가 발견되면 해당 실행을 중단한다. 임의로 순서를 맞추거나 0으로 채우지 않는다.
- 미래 프레임, 투구 후 그래픽, 전체 타석/경기 보정값이 B 처리기에 노출되면 그 실행은 투구 전 평가로 인정하지 않는다. 로그를 보존하고 원인을 고친 새 버전으로 구분한다.
- 사람이 AI 출력에 노출됐거나 방법 수정에 평가 라벨이 쓰이면 해당 비교의 독립성 주장을 중단한다.
- 원본 영상·라이브 도착 시점·출력 시점이 없어 가용성을 측정할 수 없으면 해당 지표를 `미측정`으로 남긴다. 추정 속도로 대체하지 않는다.
- 판독 정의가 모호해 합의가 안 되면 해당 사례를 `unknown`으로 보존하고 개발 자료에서 지침을 고친다. 이미 시작한 독립 평가의 지침을 몰래 바꾸지 않는다.
- 도구 오류·사용량 제한은 모델 기권과 구분한다. 실패 attempt를 보존하고 고정한 재시도 정책을 따른다. 실패 사례만 다른 방법으로 판독해 같은 버전 결과에 섞지 않는다.

## 8. 바로 다음 한 작업 단위

**독립 평가를 시작하기 전에, 기존 한 타석으로 관측 v1의 시간순 개발 리플레이를 준비한다.**

2026-10-05 CV-5는 [두 압축 창 122장의 프레임 공급](CV_PREFIX_REPLAY_V1.md)만 검증했다. 아래 실제 판독·발행 시각 기록과 전체 한 타석 검증은 CV-5a로 남아 있다.

1. 개발 경기의 한 타석을 지정하고 영상·투구 연결·frame SHA를 고정한다. 해당 타석을 독립 검증으로 부르지 않는다.
2. v1 목표 정의의 별도 판독 지시·기권 사유와 출력 기록을 만든다. M3 지시/출력은 보존한다.
3. 시점별로 제공 가능한 프레임·키·보정 스냅샷을 표로 만들고, 미래 정보는 처리기에서 격리한다.
4. 릴리스 정답은 평가자만 보관한다. 관측 결과의 발행 시점, 준비 안 됨, 픽셀만 가능, 기권을 기록하는 경로를 확인한다.
5. 시점·파일 출처 검사가 실패하면 즉시 멈추는지와 동일 입력 재생의 재현성을 확인한다.
6. 새 영상 선정 manifest와 새 라벨러 지시서 초안을 준비한다. 영상·사람·출력 마감 정의가 확보되기 전에는 독립 평가를 시작하지 않는다.

이 단위의 완료물은 **개발 리플레이 기록, 남은 사후 의존성 목록, 독립 평가 준비 manifest**다. 미트 검출 정확도 향상이나 실시간 성공을 완료 기준으로 미리 선언하지 않는다.
