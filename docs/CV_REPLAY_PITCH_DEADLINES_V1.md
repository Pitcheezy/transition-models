# 저장된 CV23/24 응답의 투구별 시간 진단 — 2026-10-08

CV23·CV24의 저장 실행을 기존 경기 747139 PA2 시각 주석에 대조했다.
판단 시작과 릴리스 양쪽의 ±0.25초 오차를 적용한 보수적 시간 조건은 **두 실행 모두 0/3구**다.
CV24의 입력 예정→발행 5초 이내 14/14는 그대로 유효하지만, 이 수치가 투구 전 가용성을 뜻하지는 않는다.
추가 모델 호출·학습 없이 저장 파일을 재검증했으며, 확정 미트는 두 실행 모두 0이다.

## 무엇을 비교했는가

각 실행의 계획된 입력 14개와 PA2의 세 투구를 모두 유지했다. 원래 익명 관측에는 투구 식별을
추가하지 않는다. 평가기에서만 원본 프레임 시각을 명시된 투구별 참조 구간에 대조하며,
이전 투구의 프레임이나 늦은 응답을 다음 투구의 관측으로 재사용하지 않는다.

기준은 변경하지 않은 [기존 수동 시각 주석](results/mlb_p0/game_747139_timing.json)이다.
이 주석은 이전 Codex·Claude 시각 검토 결과이며 사람의 독립 정답이나 프레임 단위 확정값이 아니다.
투구 키·play_id·원본 주소·manifest 연결은 기존 `validate_annotations`로 검사한다.

| 투구 | 명목상 판단 시작 D | 릴리스 R | 공통 오차 u | 보수적 입력 시작 D+u | 릴리스 오차 구간 |
|---|---:|---:|---:|---:|---|
| 747139:2:1 | 180.25 | 185.50 | 0.25 | 180.50 | 185.25–185.75 |
| 747139:2:2 | 199.25 | 200.40 | 0.25 | 199.50 | 200.15–200.65 |
| 747139:2:3 | 216.00 | 224.00 | 0.25 | 216.25 | 223.75–224.25 |

모든 시각의 단위는 같은 원본 영상의 재생 초다. 루프 시작을 첫 원본 cutoff에 대응시킨 고정 1배속
시계에서 `첫 cutoff + (응답 검증 발행 monotonic_ns − 루프 시작 monotonic_ns) / 10⁹`로
발행 시각을 환산한다. 처리 지연 때문에 시계를 다시 시작하거나 릴리스 기준을 옮기지 않는다.
피드 UTC, 실제 현장 시각, 모델 내부 `perf_counter_ns`를 이 시계와 빼거나 더하지 않는다.
준비·시작 비용을 포함하는 실제 생중계 도착 시계의 측정은 아니다.

주 결과인 `conservative_temporal_ready`는 입력 프레임이 D+u 이상이고 R−u 미만이며,
검증된 응답 발행도 R−u보다 엄격히 앞설 때만 통과한다. R−u 또는 R+u와 같은 발행 시각은
불확실 구간에 포함한다. `nominal_start_temporal_ready`는 입력 시작에 D만 적용한 보조 진단으로,
판단 시작 오차를 제외했을 때의 차이를 보여준다. 두 값 모두 미트 판독 성공이나 장면 유효성을 증명하지 않는다.

이 차이만으로 이전 주석이 틀렸다고 판정하지 않는다. 다만 `원본 PTS ≤ cutoff` 방식은
199.25초에서 앞선 클로즈업을 선택할 수 있다. 시간 조건을 통과해도 미트·자세·장면 유효성은
별도 확인해야 한다는 사례다. [화면 확인 영수증](results/cv_independent_20261008/pa2_ai_spotcheck_v1.json)은 이미지 대신 해시와 관찰 범위를 보존한다.

`conservative_window_empty=true`로 보존한다. 그러나 CLI의 기존 `validate_annotations`는
이러한 참조를 먼저 거부할 수 있다. 이를 기존 주석 계약을 위반한 입력의 CLI 지원으로 설명하지 않는다.
참조 시각이 없으면 `unmeasured`, 오류·미시도는 각각 별도로 남기며 유효한 창을 만들어내지 않는다.
