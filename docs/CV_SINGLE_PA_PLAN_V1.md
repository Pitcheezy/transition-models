## 다음 단위의 작업·완료 기준

1. 기존 캡처 영수증과 클립 SHA를 먼저 확인하고 후보 클립을 처음부터 끝까지 재생한다.
   기존 175/180/185초 및 실제 PTS 180/185/190초 이미지는 보조 자료로만 사용한다.
2. 직전 타석 종료→새 타자의 준비, 세 투구의 순서·견제/컷어웨이, 마지막 투구 결과→
   타석 종료 전환을 시각적으로 기록한다. 선수·점수판 식별은 보이는 정보만 적는다.
3. 각 경계의 마지막 이전/첫 이후 프레임을 `clip_frames`로 확보하고 실제 원본 PTS,
   디코딩 순번, 이미지 SHA, 관찰 메모, 판독자·날짜를 별도 개발 기록에 남긴다.
   요청 초·평균 fps·feed UTC를 경계 시각으로 대신 쓰지 않는다.
4. 입장 또는 종료 전환이 후보 밖이면 **전체 타석 범위 미확인**으로 유지한다.
   필요한 앞/뒤 구간만 새 캡처로 확장하고 재검증한다. 기존 클립이나 주석을 덮어쓰지 않는다.
5. 완료 산출물은 시작/끝의 검증된 실제 PTS와 세 투구 포함 여부, 잘린 경계·누락 목록,
   후속 고정 계획 JSON이다. AI 판독은 사람 라벨이나 독립 평가로 표시하지 않는다.

## 후속 실행 전에 고정할 기준

- 관측 간격은 기존 루프와 같은 **5초**다. 확인된 시작 PTS를 S로 하여 `S+5k`를 사용하고,
  종료 PTS 이하만 포함한다. 마지막 결과가 좋게 나오도록 개별 시각을 추가하지 않는다.
- 조회가 누락 구간에 닿으면 시간을 이동·보간하지 않고 명시적 미지원으로 기록한다.
  경계 확정 후 호출 수 N을 고정한다. 최초 전체 시도는 N≤12의 한 타석으로 제한한다.
  12개를 넘으면 빈도를 몰래 바꾸지 않고 실행 전 계획을 다시 정한다.
- 순차 FIFO·1배속 기준 시계를 유지한다. 늦은 요청을 삭제하거나 시계를 재시작하지 않는다.
  예정 시각, 준비 시작, 실제 호출, 프로세스 종료, `finish()` 반환 이후 발행을 모두 보존한다.
- 개발용 지연 기준은 **예정→검증 발행 ≤5초**와 **예정→호출 ≤5초**다.
  이는 검증된 사용자 허용치가 아니라 이번 계획의 한 주기 기준이다. 현재 세 샘플은 미충족이다.
- 기준 초과 응답은 늦은 결과로 남긴다. 관측 성공/기권과 시간 기준 통과를 별도로 센다.
  계획 N을 분모로 수락·모델 기권·오류·누락·지연 초과를 보고하며 중간 오류를 제외하지 않는다.
- API 오류·timeout·잘못된 JSON은 기권이 아니다. 자동 재시도·실패 후 표본 교체는 하지 않는다.
- 같은 모델/어댑터·설정·이미지 규약을 고정한다. 내부 120초/외부 240초 timeout은 실패 상한이며
  허용 지연이 아니다. 모델·코드 변경 후 실행은 새 버전으로 분리한다.

투구 전 성공은 별도로 검증한 실제 릴리스 시각과 같은 기준의 발행 시각이 있어야 평가할 수 있다.

50% 하한을 지킬 수 있을 때 진행한다. 고정 M3·시연본·사이트·팀원 파일은 변경하지 않는다.
