# CV37 Claude 교차 검토 재개

검토 대상은 우리 `Pitcheezy/transition-models`, 연구 브랜치 `codex/cv-track-pilot-1026`의 구현 고정 커밋 `cd23d7875c4f526cf3579053baa606ed19641e69`다. 실행 결과 문서는 후속 커밋에 추가되었으므로 각 소스 SHA를 `docs/results/cv_tracking_20261026/audit_v1.json`과 대조한다. 상대 저장소·운영 환경·원본 영상은 검토 범위가 아니다.

첫 Claude Code 호출은 `claude-fable-5-1`을 요청했으나 OAuth 만료401로 실행되지 않았다. 로그인만으로 검토 완료가 되는 것은 아니다. 사용 가능한 실제 모델 ID와 소스 해시·검토 결과를 남긴다. 요청 모델을 사용할 수 없으면 임의로 다른 모델로 바꾸거나 Fable 검토라고 쓰지 않는다.

## 그대로 사용할 검토 지시

우리 연구 코드만 읽기 검토하라. 파일 수정·명령 실행·외부 조회·배포·이슈 발신은 하지 말고, 제시한 코드와 실제 결과의 범위를 구분하라. 중대한 지적에는 파일/함수·구체 입력·잘못된 동작·수정 제안을 붙여라. 없으면 없다고 적고 미측정 사항을 별도로 적어라.

대상 파일:

- `intent/mitt_tracking.py`
- `intent/mitt_tracking_pilot.py`
- `tests/test_mitt_tracking.py`
- `tests/test_mitt_tracking_pilot.py`
- `docs/CV_TRACKING_PILOT_20261026.md`
- `docs/results/cv_tracking_20261026/report_v1.json`
- `docs/results/cv_tracking_20261026/audit_v1.json`

중점 확인:

1. 원본 좌표/crop 원점, 원본 JPEG SHA/PTS, frame index와 투구 결속이 맞는가. 격자 표시 이미지나 미래 관측을 추적 입력으로 사용하는가.
2. 초기 seed 이후에는 현재/과거 픽셀만 사용하는가. 잘못된 seed가 추적돼도 미트 식별로 승격하지 않는가. lost 뒤 과거 점이 현재 점으로 표시되지 않는가.
3. 패치 정규화·봉우리 차이·검색 경계·왕복 검사·NaN/시간 공백/다른 투구 거부에 구체 오류가 있는가.
4. CPU/CUDA 비교의 동기화·초기화 분리·전송/결과 회수·디코딩/캐시 영향이 올바르게 설명되는가. 속도는 정확도나 실시간 서비스 성능이 아니다.
5. 10구625프레임 결과는 공개된 개발 자료 시험이다. tracking123행과 활성 시도123회는 다른 분모이고, lost420행은10회 중단의 후속 상태다. AI54쌍 차이는 정확도가 아니다.
6. 최우선 다음 개선이 단순 임계값 완화인지, 초기 식별/변형/재탐색/후보 표시 분리인지 근거를 들어 판단하라. 새 사람 정확도나 운영 합격을 선언하지 마라.

최종 출력: 실제 검토 모델, 검토 소스, P1/P2 지적, 재현 가능한 입력, 지적 없음인 영역, 검토만으로 확정할 수 없는 부분. 새 코드를 쓰는 후속 세션은 별도 선점 후 진행한다.
