## 아침 시작 순서 (약 10분)

1. **호스트 확인(노트북 아무거나):** `app.pitcheezy.com/?game=849843`이 열리고 첫 투구가 보이는지. 안내 스위치가 꺼져 있는지(추천 카드가 보이면 꺼진 것). 11/21부터는 접근 코드도 꺼져 있어야 한다(로그인 화면이 나오면 켜진 것).
2. **모니터 2:** 팩 폴더에서 터미널 열기 → `python -B verify.py`(Windows에서 `python`이 안 되면 `py -3 -B verify.py`) → "Verified 270 files" 확인 → `python -B serve.py` → 표시된 주소 `http://127.0.0.1:8741/?pitch=849843:1:1`를 Chrome에서 열기 → 전체 화면 버튼. 터미널 창은 최소화만 하고 닫지 않는다.
3. **모니터 1:** 형 쪽 절차. 첫 타석(1회 초 Pete Crow-Armstrong 1구)에 맞춘다.
4. **폰 1대로 QR 실제 스캔** → 홈 → 서비스 열기 → 경기 화면까지 열리는지.

## 진행 중 — 두 모니터 맞추기

- 모니터 1에서 보는 공을 읽는다: 예 "9회 초 · Nico Hoerner · 2구".
- 모니터 2에서 타석 목록(같은 표기)을 고르고, 타석의 투구에서 N구를 고른다. 또는 ←/→ 키로 한 공씩.
- 이어 재생을 켜면 클립이 끝날 때마다 다음 공으로 넘어간다. 모니터 1보다 앞서가면 "이어 재생 멈추기".
- **영상이 없는 공 1개:** 9회 초 Nico Hoerner 2구(849843:69:2). 플레이어가 멈추고 "영상 제외"를 표시한다. 다음 공을 직접 고른다.
- 재생 속도는 다음 공에도 유지된다. 느리게 보여 줄 때 0.5×.

## 문제가 생기면

| 증상 | 조치 |
|---|---|
| 모니터 2에 "serve.py 터미널이 켜져 있는지 확인" 메시지 | 터미널이 닫혔다. 같은 폴더에서 `python -B serve.py` 다시 실행 → 같은 주소(8741)면 열려 있던 탭에서 "이 공 다시 불러오기". 다른 포트로 열렸다고 나오면 터미널에 표시된 새 주소로 다시 연다. |
| 클립 하나만 오류 | "다음 공 →"으로 넘어가고 끝나고 기록. |
| 모니터 2 전체 화면에서 공 표시가 안 보임 | 플레이어의 "전체 화면" 버튼을 쓴다(영상 자체의 전체 화면 버튼은 공 정보를 가린다). |
| 관람객 폰에서 추천이 안 보이고 "자료를 확인하고 있어요" | 안내 스위치가 켜진 상태다. 의도한 게 아니면 끈다(아래). |
| 호스트 장애(자료 503, 화면 깨짐) | 운영자 토큰 보유자가 **안내 스위치 ON**(절차 ops/public-host/NOTICE.md, `notice-cli.mjs --plan … --execute`). 폰 화면은 추천을 숨기고 안내만 보여 준다. 원인 해결 뒤 OFF. 모니터 1·2는 로컬이라 계속 돈다. |
| 폰이 "접속 코드" 화면 | 접근 코드가 켜져 있다. 전시 중엔 꺼야 한다(Cloudflare 설정 `ACCESS_GATE_ENABLED=false`, 사용자 계정). |
| 요청량 | Cloudflare 대시보드 Workers 요청 수를 점심·저녁에 확인. 무료 한도 하루 100,000. 화면 하나가 시간당 약 480요청이므로 열린 폰 200대·시간 정도까지 여유. 넘을 것 같으면 Paid($5/월)로 올린다(사용자 결정). |
