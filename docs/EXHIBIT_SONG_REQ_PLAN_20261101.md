## (2) 호스트 — 시험 배포, 도메인, #38 기록

**왜 ZIP을 그대로 못 올리나:** 형 앱은 `./v1/...`를 상대 주소로 읽고, 우리 Worker는 `/v1/*`를 인증 업로드로 받은 기록에서만 읽는다. 화면 4개는 정적 파일(ASSETS), 자료 24개는 업로드 API. 이 구성은 로컬에서 이미 통과했다.

**③ 시험 배포 순서(사용자 Cloudflare 로그인 필요, 각 단계 승인):**
1. 배포 후보 생성: 우리 host 고정 커밋 + 형 화면 4개 → `scripts/build_public_host_release.py`, 설정 검사.
2. 기존 시험 Worker에 새 버전 배포(`wrangler deploy`). 복구는 모든 자격 교체 이후·업로드 OFF인 후보와 현재 관리 상태를 확인하고 사용자 승인 뒤에만 한다. 무조건 이전 버전을 선택하지 않는다.
3. 설정: 자료 읽기 ON, 업로드 ON(업로드 동안만), 접근 코드 ON 유지. 발행 토큰은 새로 만들어 SHA만 등록(값은 사용자 보관).
4. 자료 24개 업로드(`publisher-cli` 24회, 제한 60회/60초 안). 업로드 OFF.
5. 검사: 공개 `/v1` 24개 바이트 = 원본 SHA, `/?game=849843` 첫 투구, 안내 ON→OFF 1회, 저장 로그 대조. (원격 바이트 검사 도구는 로컬 리허설 도구에 `--origin` 모드로 추가, 읽기 전용.)
6. #38 기록: 결과·버전 ID·파일 SHA만. 비밀·비공개 주소 제외. **발신은 사용자 승인 뒤.**

**④ 도메인:** `app.pitcheezy.com`은 앱, `www.pitcheezy.com`은 새 홈, 영상은 `media.pitcheezy.com`으로 분리했다. apex는 Sites 연결이 남아 있어 아직 옛 홈이다. 다음은 기존 Sites 사이트를 보존하고 apex 도메인 연결만 해제하는 전환안이다. 실행 전 정확한 Route·DNS·TLS와 복구 조건을 확인하고 사용자 승인을 받는다. 절차는 [현재 인계](CODEX_HANDOFF_EXHIBIT_20261101.md)와 [홈 README](../ops/public-home/README.md)를 따른다. 기존 QR의 주소는 바뀌지 않는다.

**공개 범위:** 시험(11/11)까지 접근 코드 ON. 전시 리허설(11/21)부터 OFF를 목표로 하되 일반 공개 전환은 별도 승인 뒤 적용한다. 안내 문구는 "잠시 자료를 확인하고 있어요. 곧 다시 보여 드릴게요."로 결정됐고 코드 반영·검토·배포가 남는다.
**요청량:** 열린 화면 1개 ≈ 시간당 480요청(로컬 측정). Free 하루 100,000요청 → 켜 둔 화면 기준 하루 약 200화면·시간. 전시 당일 감시하고, 위험하면 Workers Paid($5/월).
