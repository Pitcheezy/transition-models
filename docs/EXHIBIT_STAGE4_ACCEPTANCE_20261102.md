## 대상과 완료 기준

- 최초 관리 대조 기준 버전은 `5999cf0d-4f18-4d43-bcd6-320e04860369`. 실행 직전 버전·업로드 OFF·접근 ON·수집/피드백 OFF를 관리 조회로 다시 확인한다. 다르면 시작하지 않는다. 관리 읽기 조회는 서비스 요청 원장과 구분한다.
- 정적4·보조 설정1·자료6의 실제 응답 바이트, 인증, 제외 주소404, 열린 화면 안내 숨김·복원과 실제 시계 폴링을 확인한다. **폰 실기기 결과와 저장 서버 로그 대조는 별도 증거**다.
- 홈·현재 공개 앱·영상·도메인·DNS·Route·자격·배포는 변경하지 않는다. 자료 업로드는 계속 OFF다. 형 빌드 바이트를 수정하지 않는다.

## 승인할 한 단위와 유한 원장

이번 단계는 단일 시험 호스트에서 읽기 검사와 안내 ON/OFF를 함께 실행하는 한 단위다. 사용자 이전 승인에서 단계4가 별도로 지정되었으므로 실행 전 한 번 승인받는다. `--execute`와 비공개 입력의 `approved=true`가 모두 필요하다. 준비 입력은 false다.

1. **고정 HTTP 인수: 최대24요청.** 쿠키 없는 GET `/`, `/favicon.svg`, `/v1/manifest.json` 각401·접근 헤더(3); 업로드 HEAD503(1); 기존 검사18(로그인1, 자료6, 정적4, 홈/경기진입2, 없는 경기1, 제외 주소3, manifest HEAD1); 보조 설정 바이트1; 로그아웃1. 정상 기존 검사19판정을 재사용한다. 오류 뒤 일반 송신을 멈추고 인증했다면 예약된 로그아웃1회만 보낸다. 제외된 평가 자료는 상태만 확인하고 본문을 읽지 않는다.
2. **브라우저 단일 탭: 최대180요청.** Chrome의390×844 탭1개에서 초기접속·로그인·정적로딩·폴링·안내 관찰·로그아웃을 모두 센다. 일반 요청179 + 마지막 로그아웃1을 강제한다. 일반 상태를 실제600초 관찰하고, 안내 숨김/합성오류 관찰/복원은 각각 최대120초만 기다린다. 이는 관찰 한도이며 응답 보장이 아니다. DOM 확인 자체는 새 HTTP 요청을 만들지 않는다.
3. **안내 관리: 최대8요청.** 정상 GET상태 → 조건부 PUT ON → GET새상태 → 조건부 PUT OFF → GET종료상태(5). 추가3회는 응답 불명확 시 상태 조회·자기 변경 종료·최종 확인을 위한 예약 예산이다. 무조건 같은 PUT을 재시도하지 않는다. 메시지는 `maintenance`의 승인 문구만 사용한다.

**자동 서비스 요청 총 상한은212회(24+180+8)**다. 상한은 예상 사용량이나 수용량이 아니다. 안내5회가 정상이므로 실제 횟수는 이보다 작을 수 있다. 각 구간의 남은 예산을 다른 구간으로 전용하지 않는다. 모든 요청은 송신 전 시작 원장, 수신 후 UTC·방식·경로·status·Ray를 남긴다. 관리 버전 핀은 요청별 서버 버전 확인으로 주장하지 않는다.

브라우저의 일반 오류 검사는 안내로 추천이 숨겨진 뒤 game 요청 하나 이상에 **브라우저 내부에서만 합성500**을 반환한다. 실제 서버 장애를 만들지 않는다. 합성 응답은 원격 요청수에 넣지 않고 별도 기록한다. 실제 안내503·복원200과 합성 오류 증거를 섞지 않는다.

## 중단과 안내 복구

- 입력 SHA/버전 불일치, 예상 밖 주소·응답, 전송 오류, 기록 실패, 횟수 초과, 화면 검사 실패 시 다음 일반 요청을 중단한다. 자동 업로드·자격 교체·재배포는 없다.
- 처음부터 안내가 켜져 있으면 시험을 시작하지 않는다. ON은 최초 ETag 또는 `If-None-Match:*`, OFF는 이번 실행이 소유한 정확한 ETag만 사용한다.
- ON 응답을 잃으면 먼저 저장 상태를 읽는다. 고유 실행 ID·감사 기록·예상 revision 또는 확인된 쓰기 ETag로 자기 변경임을 입증한 경우에만 조건부 OFF한다. 다른 변경/412는 덮어쓰지 않는다.
- OFF 응답을 잃어도 같은 쓰기를 반복하지 않고 종료 상태를 조회한다. 응답/감사 증거가 불완전하면 OFF 확인과 전체 합격을 구분한다.
- 운영자 충돌·통신 단절·프로세스 강제 종료처럼 자동 OFF를 입증할 수 없는 경우에는 **복구 미확인/HOLD**로 보고한다. 어떤 프로그램도 강제 종료 뒤 복구를 보장한다고 쓰지 않는다. 비공개 원장을 보존하고 기존 안내 CLI로 현재 상태를 읽은 뒤 사용자가 승인한 동일 종료 범위에서 처리한다.
- 브라우저 인증을 시도했다면 마지막 로그아웃을 예약한다. 로그아웃 실패·미완 요청은 합격으로 처리하지 않는다. 쿠키 원문을 영수증에 기록하지 않는다.

## 실행 준비물과 재현

비공개 입력과 결과는 기존 비공개 작업 폴더의 `stage4-preparation/`·`deployment-stage4/`에 한곳으로 둔다. 호스트·계정·자격 파일 경로와 값은 Git/이슈에 옮기지 않는다. 접속 코드/안내 토큰은 기존 파일에서 메모리로 읽고 명령줄에 넣지 않는다. 새 열쇠 발급은 없다.

```text
node --test ops/public-host/tests/exhibit-stage4-transport.test.mjs ops/public-host/tests/exhibit-stage4-read.test.mjs ops/public-host/tests/exhibit-stage4-browser.test.mjs ops/public-host/tests/exhibit-stage4-notice.test.mjs ops/public-host/tests/run-exhibit-stage4.test.mjs
node ops/public-host/run-exhibit-stage4.mjs --input <비공개 승인=false 입력>
# 승인과 관리 재대조 후에만, 같은 고정 입력의 approved를 갱신하고 실행:
node ops/public-host/run-exhibit-stage4.mjs --input <비공개 승인 입력> --execute
```

기존 실행 결과 폴더가 있으면 재실행하지 않는다. 다른 폴더로 바꿔 실행을 반복하는 것도 새 실행으로 다룬다. 실패 원장을 보존하고 원인·남은 예산·안내 상태부터 확인한다.
