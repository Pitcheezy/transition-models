## 4. V4에서만 생긴 문제

### 4.1 합의·전시 구성

- Song 파일이 공개 주소에서 아예 사라지고 탭 제목이 바뀌었다. Song의 `/assets/*` 주소는 404가 아니라 V4 index.html이 200으로 나간다(11/11 실측).
- 관전 화면 담당이 Song에서 우리로 바뀌었다. 배포 검사기의 "Song 저장소 빌드만" 규칙을 임시로 풀었고, 11/2 인수 검사 도구는 Song 화면 문구·경로에 고정돼 있어 V4 합격 기준으로 쓸 수 없다.
- Song의 요청(틀·비율 유지, 사용자가 11/9에 전달)을 V3는 지켰고 V4는 지키지 않는다.
- [운영표](EXHIBIT_OPERATIONS_20261101.md)의 "완료 경기 탐색·모니터 1 대체" 행(10행), "문제가 생기면" 표의 증상 문구(40·41행)는 Song 화면일 때만 맞다.
- 머리 점수가 "던지기 전 값"이고, 아래 메뉴 5칸·자동 진행·3D 타자·유니폼 색·라인업 화면은 Song 화면과 포스터가 설명하지 않는다. 포스터는 11/1에 원본 이미지를 받아 QR만 해독했고 앱 화면이 실린 부분은 아직 대조하지 않았다. 모니터 1의 실제 화면은 우리가 본 적이 없다. 그래서 항목별 대조는 못 했다(11/12 정정).

### 4.2 동작 (소스 판독, V4로 실제 시험한 적 없음)

핵심은 한 줄이다. **V4는 경기 파일을 처음 열 때 한 번만 읽고 다시 읽지 않는다**(공개본 relay-v4.js:215, 다른 타이머는 자동 진행·연출·3D 재시도뿐).

| 상황 | v0 (Song 화면) | V4 |
|---|---|---|
| 긴급 안내 ON | 열린 화면도 추천·존·목록을 숨기고, OFF 뒤 새로고침 없이 복원(11/1 로컬 Chrome 약 9~10초 / 3~4초) | 열린 화면은 추천을 계속 보여 줌. 새로 열거나 새로고침한 폰만 안내 페이지(503)를 봄 |
| 접근 코드 ON, 세션 60분 만료 | "접근 확인이 필요해요" 알림 | 열린 화면에 아무 표시 없음. 새로고침하면 코드 입력 화면. 이 조합은 배포된 적 없음 |
| 읽기 실패(5xx·망 끊김) | 4초 재시도, 15초 시간 제한, 원인별 문구 | 문구 하나("경기 기록을 불러오지 못했어요…"), 재시도·다시 시도 버튼 없음 |
| 새 발행(run) | 10초 확인으로 열린 화면에 반영, 뒤로 간 순번 거부 | 새로고침해야 반영, 순번·신선도 검사 없음, 투구 0개 파일은 실패 화면 |
| 재방문 | ETag로 304 | 매번 약 727 kB 다시 받음 |

- Song 화면의 "이 화면의 기준과 한계" 문장(추천은 검증 전 실험 버전 등)이 V4에 없다.
- Song 화면은 메인 존에 포수 미트 표시를 그리는데 V4는 자세히 시트에만 그린다(미트 가로 값이 있는 공은 262구 중 27구).
- 운영표 41행 "폰 화면은 추천을 숨기고 안내만 보여 준다"와 규약의 "누구든 즉시 공개 화면을 안내 문구로 바꿀 수 있다"는 열린 V4 폰에는 성립하지 않는다. 11/10 배포 기록의 "안내 스위치가 V3 때처럼 화면에 적용된다"는 새로 여는 화면에만 맞다.

## 6. V4를 관람객 화면으로 남기려면 (각 단계는 별도 승인)

1. Song 동의와 차이 목록 합의를 #38에 남긴다. 10/31 "고정 빌드" 문장을 대체하는 합의 문장이 필요하다.
2. V4에 가벼운 주기 확인을 넣는다. 화면이 보이는 동안 작은 파일을 주기적으로 읽어 안내 응답이면 추천·존·목록을 숨기고 안내 문구를 보여 주고, 정상이면 복원한다. 401이면 재접속 안내, 실패 시 재시도와 시간 제한. 넣지 않기로 하면 그 한계를 Song과 운영표에 적는다.
