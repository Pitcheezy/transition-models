## 문제와 수정

`intent.run.build_records`가 timing의 같은 투구 키를 중복 수용하고,
포인트의 `frame_seconds=NaN`을 정상 결정 프레임과 연결하는 결함을 확인했다.
비유한 수에서는 `abs(frame_seconds - decision_seconds) > 1e-6`가 거짓이므로
시각 불일치 검사를 우회했다. 오류 재현은 메모리에서 복제한 입력에만 적용했다.
기존 저장 결과에서 오류가 발생했다는 주장이 아니다.

- 849843 정상 자료: 39행 / 39고유 투구 키.
- 같은 annotated timing 행을 복제: 수정 전 40행 / 39고유 키를 출력했다.
- 포인트 시각을 NaN으로 교체: 수정 전 정상 기준과 같은 39행을 출력했다.
- 현재는 두 경우 모두 카메라 계산·이미지 읽기·결과 파일 쓰기 전에 거부한다.

모든 timing 행은 상태와 관계없이 키가 고유해야 한다. annotated 결정 시각과 모든
포인트 프레임 시각은 숫자·유한·0 이상이어야 하며 bool/문자열/미세 음수는 거부한다.
선택되지 않은 포인트도 카메라 추정에 들어가므로 같은 검사를 한다.
고유한 unavailable timing의 null 시각과 정상 0초, 누락 포인트의 기존 기권 동작은 유지한다.
기존 1e-6초 연결 허용 오차·정렬·좌표 변환·출력 스키마는 그대로다.
