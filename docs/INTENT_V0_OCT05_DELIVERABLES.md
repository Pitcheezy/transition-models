## 제출 체크리스트

- [ ] **사람 라벨:** 개발 경기와 분리된 평가 경기 **2개 이상**, 사람이 미트 위치를 표시한 투구 **합계 50구 이상**.
  기존 블라인드 라벨 팩과 라벨러 지시를 유지한다. AI 점·판독 결과를 정답으로 복사하지 않는다.
  경기별 시도 수·사람 표시 수·기권 수와 이유를 구분한다. 기권을 표시한 50구에 포함하지 않는다.
  표본이 부족하면 기존 계획의 보충 경기 규칙을 따른다. 새 임의 선별이나 유리한 사례만의 제출은 하지 않는다.
- [ ] **라벨 출처:** 실제 사람 라벨 파일과 사용한 팩 ID, 경기·투구·프레임 식별 정보,
  라벨링 날짜와 담당자 식별자(익명 가능)를 제공한다. 기존 형식을 유지하고 재현에 필요한 파일 경로를 적는다.
- [ ] **정확도 보고서:** 기존 `docs/results/mlb_p0/intent_accuracy_report_v0.json`을 갱신한다.
  경기별 및 평가 경기 합산으로 표본 수, 미트 픽셀 거리와 출력 피트 오차의 중앙값·90분위,
  가로·세로 오차, AI/사람 각각의 기권률과 가용성을 보고한다. 개발 경기 수치를 합산하지 않는다.
  실제 비교 가능한 표본 수는 사람 표시 수와 다를 수 있으므로 지표별 분모를 명시한다.
- [ ] **보정과 해석의 한계:** 미트 판독 오차와 카메라 좌표 변환 오차를 분리한다.
  같은 변환 행렬을 사용한 사람·AI 비교가 물리 좌표의 정확도까지 증명하지 않음을 적는다.
  823407의 좌우 카메라 각도 미측정, 낮게 놓인 미트의 높이, 압축 영상의 표본 편향 등
  알려진 한계와 이번 검증에서 추가 확인한 실패 사례를 남긴다. 못 잰 값은 null/미측정으로 둔다.
- [ ] **재현·연동 정보:** 코드 커밋, 사용한 출력 JSONL·라벨·보정·보고서 경로,
  실제 재현 명령과 필요한 환경, 실행 결과 및 관련 스키마 검사 결과를 적는다.
  평가 중 코드·규칙 변경이 있었다면 고정 방법과의 차이 및 이유를 공개하고 이전 결과를 덮어 감추지 않는다.
- [ ] **시연용 짧은 요약:** 한 문단 또는 작은 표로 “무엇을 했는지 / 몇 경기·몇 구인지 /
  측정 오차 / 미측정·실패 / 화면에서 보여줄 수 있는 범위”를 정리한다.
  설명용 사례가 있으면 pitch_id로 연결하고 대표 사례인지, 성공·실패 예시인지 표시한다.

## 전달 위치와 완료의 뜻

- 작업 브랜치 `feature/intent-v0` 또는 그 후속 PR에 보고서·요약·재현 안내를 올리고 최종 커밋을 알려준다.
- 제출 파일 목록과 재현 명령은 `docs/INTENT_V0_M3_EVAL.md`에 모아도 된다. 이름만 다른 중복 보고서를 만들 필요는 없다.
- 사람 라벨은 공유 가능한 형태로 제공한다. 영상·프레임·라벨링 HTML 등 기존 git 제외 자료는 공개 저장소에 추가하지 않고,
  기존 허용된 전달 방식과 파일 식별자를 안내한다. 전달 방법이 없으면 막힌 항목으로 명시한다.
- **완료 = 요구 표본을 확보하고 측정·출처·한계·재현 자료를 전달한 상태.** 오차가 크거나 성능이 좋지 않아도 사실대로 측정했다면 보고할 결과다.
  M3 측정 완료는 서비스 채택·9구역 사용 승인·투수 의도 검증·추천 정책 우위 입증을 뜻하지 않는다.
- 10/5까지 전부 끝나지 않으면 **부분 결과를 같은 기한에 전달**한다: 확보 표본, 가능한 지표,
  미완료 항목, 막힌 이유, 예상 완료 시각. 표본 부족을 완료로 표시하지 않는다.
