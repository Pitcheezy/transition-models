# 10/6 우리 CV 발표 — 첫 타석 실제 영상·저장 응답 동선

2026-10-06. 오프라인 v4용 안내다. 공식 영상 3구와 제공받은 실제 저장 응답을 중심으로
약 2분을 목표로 한다. 실제 낭독 시간은 미측정이며 Song의 전체 5분 시연·실기기 리허설과 별개다.

## 먼저 열기

전달 ZIP 전체를 압축 해제하고 `START_HERE.html`을 연다. 첫 링크로
`site/receiver.html?demo=849843-pa1`에 들어간다. 기본 시연은 저장 파일을 사용해 모델 호출·로그인·
인터넷이 필요하지 않다. 브라우저가 파일 기능을 제한하면 README의 로컬 HTTP 방법을 사용한다.

시연 경기(2026-09-29 컵스 @ 파드리스, 849843)와 고정 M3의 평가 경기
(필리스 @ 브레이브스, 849845; 레이스 @ 필리스, 823407)를 구분한다.
홈·서비스의 콘셉트 예시 수치를 첫 타석의 실제 저장 응답과 섞어 설명하지 않는다.

## 발표 직전 열어 둘 것

1. [공개 첫 타석](https://pitcheezy.com/receiver.html?demo=849843-pa1) 또는 오프라인
   `site/receiver.html?demo=849843-pa1` — Michael King 대 Pete Crow-Armstrong, 1구부터.
2. `slides/intent_cv_summary_20261006.png` — 기존 M3 요약 장표.
3. `comparison/index.html` — 대표 `849845:10:4`(크리스 세일 대 브라이슨 스톳).

첫 타석은 **결과 숨김**으로 시작한다. 구종 선택 비중을 먼저 보고 **투구 영상 재생**을 누른다.
각 약 7초 영상이 끝나면 저장된 실제 결과가 표시되고 다음 구로 이동할 수 있다.
3구 결과 공개 후에만 **미트 판독 장면**을 눌러 별도의 고정 정지 장면을 확인한다.
**영상으로 돌아가기**를 누르면 미트 표시가 사라지고 공식 영상으로 돌아간다.
발표 중 파일 수신·합성 예시·새 모델 호출은 필요 없다.

## 발표 순서 — 목표 시간이며 실제 계측 아님

| 목표 구간 | 조작 | 핵심 |
|---|---|---|
| 0:00–0:15 | 첫 타석 1구 추천 확인 | 실제 전달받은 저장 응답, 구종 선택 비중 |
| 0:15–0:50 | 1구 재생·결과 → 2구 → 3구 재생·결과 | 공식 투구 영상 3개와 사후 저장 결과 |
| 0:50–1:05 | 3구 미트 판독 장면 | 기존 3084번 정지 프레임에만 미검토 AI 표시 |
| 1:05–1:45 | M3 요약 PNG → 대표 849845:10:4 | 평가 86/58/28, 범례와 확정 문구 |
| 1:45–2:00 | 대표 그림 유지 | 검증 한계와 다음 작업 |

1·2구에는 저장 미트 주석이 없다. 3구의 초록 점은 기존 condensed 영상의 3084번 정지 프레임에
대응하며 움직이는 공식 영상의 추적 결과가 아니다. 새 공식 클립의 시간축·좌표로 옮기지 않았다.
결과 숨기기나 투구 전환은 재생·미트 표시를 초기화한다. **현재 투구 결과 공개**는 영상을 보지
않고 저장 결과를 여는 수동 대안이다. 영상 종료도 저장 결과를 보여 주는 계기일 뿐 자동 판정이 아니다.

## 읽을 대사

저희는 한 공의 추천과 실제 결과를 비교해 경기를 더 쉽게 이해하도록 돕는 서비스를 만들고 있습니다.
저는 영상에서 포수 미트를 읽고 검증하는 CV 부분을 맡았습니다.

지금은 컵스와 파드리스의 첫 타석입니다. 실제로 전달받은 모델 응답을 저장해 보여 주며,
이 비율은 구종 선택 비중입니다. 스트라이크나 안타가 일어날 확률은 아닙니다.
공식 영상으로 세 구를 보고, 각 영상이 끝나면 저장된 실제 결과를 확인합니다.

3구에서만 별도로 판독한 정지 장면을 열 수 있습니다. 초록 점은 이 장면에 저장된
미검토 AI 미트 중심입니다. 영상 전체를 추적한 결과나 포수의 실제 요구 위치는 아닙니다.

CV 평가는 별도 두 경기에서 했습니다. 전체 86장 중 AI 출력은 58장, 기권은 28장입니다.
대표 그림은 크리스 세일 대 브라이슨 스톳 사례이며, 초록 원은 AI, 빨간 십자는 사람 표시입니다.

> 평가 2경기에서 AI와 사람이 모두 표시한 58구의 미트 점 차이 중앙값은 2.5px입니다.
> 같은 변환 기준의 좌표 차이는 중앙값 약 1.1인치이며, 물리 정확도나 투수 의도를 검증한 값은 아닙니다.

현재 확인한 것은 저장 응답·투구 영상의 대응과 미트 판독의 사람 표시 대비 차이입니다.
실시간 추론이나 자동 중계 동기화, 제구 실책 판정은 아닙니다. 다음은 미트 주석의 독립 검토와
새 영상 검증, 실제 연속 입력의 처리 시간·공개 시점 확인입니다.

## 질문 대응 — 홈·콘셉트·추가 자료는 여기서

- **최종 제품은 어떤 모습인가요?** 홈·서비스를 열어 설명한다. 예시 확률·선수 평가·교체
  비교는 이번 첫 타석의 실제 저장 응답과 구별한다.
- **모델 연결은 어디까지 됐나요?** 실제 첫 타석 응답을 수신해 공식 3구 영상과 연결했다.
  과거 저장 응답의 재생이며 실시간 API 호출·모델 실행 검증은 아니다. 자료 생성 커밋과
  실행 서버의 정확한 커밋도 구별한다. 합성 수신 예시는 별도 테스트다.
- **추천 위치가 포수 요구인가요?** 과거 실제 도달 분포의 근사다. 구종 선택 비중은
  사건확률이 아니며 추천 위치도 실제 요구 위치나 검증된 목표 정책을 뜻하지 않는다.
- **1구 카운트를 영상에서 읽었나요?** 첫 프레임에는 메인 점수판이 없다. 상황은 공식 기록에
  근거한다. 우상단 BOS/NYY는 다른 경기 알림이며 이 타석 점수판이 아니다.
- **투수의 실투를 판정하나요?** 미트와 공의 측정 평면이 달라 차이를 제구 오차로 계산하지
  않는다. 미트 높이·포수 요구·투수 의도도 검증하지 않았다.
- **1.1인치가 실제 정확도인가요?** 동일 변환 기준에서 58구의 AI·사람 x·z 좌표 거리를
  비교한 중앙값이다. 물리 정확도, 가로 오차, 대표 한 구의 오차가 아니다.
- **다른 관측도 있나요?** 저장 리포트는 39구 / 좌표 27 / 기권 12다. 기권 사례
  `report.html?pitch=849843%3A2%3A5#analysis`와 성공·실패·FOX 비교 그림은 질문 때만 연다.
- **기권은 모두 올바른 판단인가요?** AI 기권 28장 중 26장은 사람이 표시했다.
  기권을 모두 정답으로 세지 않고 출력 수와 공동 표시 사례의 차이를 함께 제시한다.
- **자동·실시간인가요?** 투구별 공식 클립이며 투구 사이까지 이어지는 연속 중계가 아니다.
  실제 판독 지연·사전 가용률·자동 동기화는 미검증이다. 이번 프레임 확인은 AI 점검이며
  새로운 사람 간 일치도 평가나 독립 정확도 검증이 아니다.
- **팀원과 역할이 겹치나요?** 팀원은 모델·확률·정책·실제 관전 서비스를 맡는다.
  나는 미트 판독·좌표·검증, 독립 설명용 사이트와 받은 응답의 연결을 준비했다.

## 배포·보존 범위

지정 팀원에게 비공개 파일로 전달하거나 현장에서 여는 묶음이다. comparison/의 기존 비공개
취급을 유지하며, 공식 영상 공개 허용을 ZIP 전체의 공개 업로드 허용으로 확대하지 않는다.
이 문서 작업에서 팀원에게 보내지 않았다. 모델 체크포인트·사람 원본 라벨·private 세션·
전체 영상·API 인증정보는 포함하지 않는다.

기존 M3·JSONL·PPTX·PNG·비교 HTML은 변경하지 않는다. 파일별 해시는 `bundle_manifest.json`을
참조한다. 파일 바이트 검사이며 모델 진위·실시간 성능 인증은 아니다. 재생성·검증 방법은
`docs/PITCH_STUDIO_OFFLINE_BUNDLE.md`에 있다.
