# SNY 선수 이름 OCR 개발 기준선 — F-4a

이 구현은 경기 747139의 **한 SNY 화면 형식·PA6 여섯 프레임**에서 이름 문자열을 읽는
개발 기준선이다. 선수 이름 OCR의 실행 경로와 평가 출처를 분리하는 첫 단계이며,
F-4a 전체 완료, 일반 중계 인식, 새 독립 정확도 또는 실시간 선수 추적을 뜻하지 않는다.
수동 판독·feed 기준·교체/신선도 규칙은 [선수 식별 규약](PLAYER_IDENTITY_PROTOCOL.md)을 따른다.

## 실행 환경과 재현 범위

[Windows OCR bridge](../src/vision/windows_ocr.ps1)는 운영체제에 이미 설치된 Windows OCR의
`en-US` 엔진을 호출한다. 네트워크, 외부 유료 API, 모델 자동 다운로드 또는 패키지 설치를
수행하지 않는다. 인식에는 **Windows PowerShell 5.1**이 필요하다. PowerShell 7에서는 이
WinRT 호출 경로를 지원하지 않으므로 Python 어댑터가 Windows의 5.1 실행 파일을 명시한다.

2026-09-28 개발 실행에서 반환된 환경은 다음과 같다.

| 항목 | 기록값 |
|---|---|
| 엔진 | `windows_ocr` |
| 언어 | `en-US` |
| OS version | `10.0.26200.0` |
| OCR DLL file version | `10.0.26100.9278 (WinBuild.160101.0800)` |
| DLL 경로 | `C:\Windows\System32\Windows.Media.Ocr.dll` |

저장소의 `uv.lock`은 이 운영체제 구성요소와 언어 모델을 고정하지 않는다. Windows 업데이트로
인식 결과가 바뀔 수 있어 실행 환경·설정·코드 해시와 실제 출력 문자열을 함께 저장한다.
버전 문자열은 언어 모델 전체 바이트를 고정한 체크포인트와 같지 않다.

현재 **Mac에서 새 예측을 생성하는 backend는 없다.** Mac에서도 저장된 예측의 구조 검사와
채점은 가능하다. 저장된 결과를 재채점한 것을 Mac에서 OCR을 다시 실행한 결과로 보고하지 않는다.
맥용 인식 엔진은 별도 어댑터·버전 기록·검증을 거쳐 추가해야 한다.

## 이미지 입력과 판독 흐름

구현은 [sny_player_names.py](../src/vision/sny_player_names.py)의 `SNYPlayerNameReader`다.
`read(frame)`에는 PIL 이미지 하나만 전달한다. 투구 키, 예상 이름, 선수 ID, feed matchup이나
이름 후보 사전을 전달하지 않는다. 원문 OCR을 정답 선수에 맞춰 고치지 않는다.

현재 고정 설정은 다음과 같다. 좌표는 원본 1280×720 이미지의 PIL crop 좌표이며 오른쪽·아래
경계를 포함하지 않는다.

| 단계 | 현재 규칙 |
|---|---|
| 화면 크기 | 정확히 1280×720, 다른 크기는 기권 |
| 중계 그래픽 확인 | 기존 SNY 점수판의 `bug_present` gate |
| 투수 이름 영역 | `(64, 111, 168, 129)` |
| 타자 이름·타순 영역 | `(64, 133, 252, 151)` |
| 이름 패널 확인 | 채널 최솟값 `>160`, 채널 범위 `<50`인 픽셀 비율이 0.5 이상 |
| 잘림 의심 | 오른쪽 경계에 어두운 글자 픽셀이 걸리면 보수적으로 기권 |
| 전처리 | 회색조, LANCZOS 4배 확대, 흰색 테두리 16px |
| 문자열 파서 | 공백·대소문자 정규화 후 제한된 라틴 이름 문법; 타자는 먼저 1–9 타순 읽기 |
| 시간 상태 | 해당 프레임만 사용; 이전 이름 유지 없음 |

패널이 없으면 해당 영역의 OCR을 호출하지 않고 `name_panel_absent`로 기권한다. 점수판 gate가
닫히면 두 역할 모두 기권한다. 잘린 이름 의심 규칙도 완전한 이름 판별기가 아니라 고정 crop의
일부 위험을 줄이는 장치다. 긴 이름·다른 배너 폭·다른 폰트·해상도·중계사에 대한 동작은 검증하지 않았다.

개발 중 crop 아래쪽의 수평 구분선을 글자로 오인하는 현상을 확인해 투수/타자 영역의 아래 경계를
각각 131→129, 153→151로 조정했다. 같은 PA6 프레임에서 바꾼 기하 설정이므로 이 조정 이후 결과도
개발 재채점이다. 선수 정답 문자열을 이용한 교정은 하지 않는다.

파서는 문자열이 문법적으로 유효하다는 사실만 판정한다. 문법을 통과한 오인식도 가능하므로
`read`는 올바른 선수 확인을 뜻하지 않는다. 퍼지 매칭, 접두사 완성, `0/O` 등의 정답 기반 보정은
수행하지 않는다. 인식하지 못한 이름을 해당 타석의 공식 선수 이름으로 채우지 않는다.

Python backend는 한 프레임의 통과한 crop들을 순서대로 임시 PNG에 저장해 한 번의 bridge 호출로
처리한다. bridge는 입력 순서를 보존하고 Python이 결과 개수와 문자열 형식을 검사한다.
임시 파일은 저장소의 `.cache/player-name-ocr` 아래에 만들고 실행 후 정리한다.
PowerShell 호출의 제한 시간은 60초다. 엔진 실패·시간 초과를 조용한 성공이나 빈 정답으로 바꾸지 않고
`error` 및 원인을 남겨 평가 기회에서 빠지지 않게 한다.

## 판독, 이름 대응, 공식 기준의 분리

[평가 코드](../src/evaluation/player_identity_ocr.py)는 세 단계를 구분한다.

1. 이미지에서 나온 `raw_text`, 파서의 `name_text`·타순·기권/오류 원인을 저장한다.
2. 읽힌 이름을 동결된 경기 **전체** 명단의 이름/별칭에 정확히 대응한다. 사전 후보가 하나일 때만
   ID를 얻는다. 기대 역할·정답 matchup ID를 이용해 동명이인을 고르지 않는다.
3. 대응된 ID를 공식 최종 feed의 replay 기준과 비교한다. 이 비교는 OCR 입력이 아니다.

화면 문자열이 틀린 경우, 읽힌 문자열은 맞지만 이름이 모호한 경우, 원문을 읽지 못한 경우를
따로 볼 수 있어야 한다. 타순은 별도 화면 필드이며 ID 대응에 사용하지 않는다. 현재 이름 reader는
팀도 판독하지 않는다. 프레임·투구·역할은 목록 위치가 아닌 고정 키, `play_id`, 증거 해시로 대조한다.
누락·중복 예측을 거부하고 기권과 엔진 오류를 명시적으로 남긴다.

feed와 최종 선수 명단은 과거 경기 재생 기준이다. 당시 실제로 도착한 입력이나 실시간 교체 상태를
증명하지 않는다. 영상 판단 시점은 기존 **수동 timing**에서 가져오며 이 OCR이 자동 동기화를 구현하지 않는다.
현재 프레임의 이름 판독으로 교체 감지·이전 선수 유지·실시간 tracker를 완성했다고 해석하지 않는다.

이미 알려진 장면을 본 AI-assisted, 비블라인드 개발 라벨이며 사람 간 독립 일치도가 아니다.

| 이름 기회 | 6프레임 × 투수/타자 = 12 |

| 문맥 진단 | 470.00초의 일부 가린 `OZUN…`; 본 평가 합계에서 분리 |

470초 소개 그래픽은 완전한 이름 정답도, 이후 481초의 타자 이름을 채울 근거도 아니다.
본 평가의 한 부재 사례와 별도 소개 화면 진단은 negative gate의 제한적인 확인이다.
다양한 광고·리플레이·관중·자막에서 거짓 판독이 없음을 입증하지 않는다.

이름의 판독 시도·정답·오답·기권, 이름 대응 후 ID 결과, 타순, 엔진 오류를 분리해 보고한다.
분모 전체의 coverage와 시도한 항목에서의 정확도를 함께 보아야 한다. 적게 읽고 많이 기권한
결과의 높은 조건부 정확도를 전체 인식 성공률로 바꾸어 표현하지 않는다.
문맥 진단을 더해 본 평가의 표본 수나 정확도를 늘리지 않는다.

이 여섯 프레임으로 crop과 파서를 조정했으므로 결과는 **개발 재채점**이다. 경기 747139 전체도
이미 검토된 개발·시연 자료다. 새 독립 성능을 주장하려면 이전에 보지 않은 영상과 동결된 규칙이 필요하다.

출력한 이름 9건의 정답 비율 100%를 전체 인식 성공률로 표현하지 않는다. 투수6건은 모두 읽었고,
타자는 표시된5건 중3건을 읽었다. 481초 타자는 이름 패널이 없어 기권했다.
611.45초 타자는 OCR 원문이 빈 문자열이고, 663.50초 타자는 `3.0ZUNA`였다. 후자는 이름에 숫자0이
포함돼 거부했으며 타순3만 보존했다. 0을 O로 바꾸거나 정답 `OZUNA`로 대체하지 않았다.

이는 한 환경의 반복 확인이며 다른 Windows 버전이나 Mac에서 동일 인식을 보장하지 않는다.

PA61 네 투구의 이름 판독 근거와 고정 v1 평가는 2026-09-28에 아래 절로 마쳤다. 투수의 성 `IGLESIAS`는 경기 명단에서

현 기준 생성기가 거부한다. 이 제한을 없애려고 최종 matchup을 과거 투구에 무조건 덮어쓰지 않는다.

## bridge 단독 확인

저장소 루트의 PowerShell에서 설치된 엔진 정보를 확인할 수 있다.

```powershell
& "$env:SystemRoot\System32\WindowsPowerShell\v1.0\powershell.exe" `
  -NoProfile -NonInteractive -ExecutionPolicy Bypass `
  -File src/vision/windows_ocr.ps1 -Info
```

`-InputJson`은 로컬 이미지 경로의 UTF-8 JSON 배열 파일을 받는다. `-Info`와 동시에 사용하지 않는다.
정상 종료 시 stdout에는 아래 구조의 JSON만 출력한다. 빈 이미지에서 글자를 찾지 못한 정상 결과와
이미지 파일을 열지 못한 오류는 다르다. 잘못된 파일/엔진 오류는 stderr와 0이 아닌 종료 코드로 실패한다.

```json
{"engine":"windows_ocr","language":"en-US","os_version":"...","dll_version":"...","results":[{"text":"...","lines":["..."]}]}
```

엔진은 **bridge 프로세스당 한 번** 만든다. 현재 backend는 프레임마다 새 프로세스를 띄우므로
실행 시간에는 PowerShell 시작·WinRT/엔진 초기화·파일 저장과 인식이 포함된다. `-Info` 시작도 별도다.
현재 측정값은 지속적인 실시간 영상 처리량이나 OCR 모델 순수 추론 지연이 아니다.

## 평가 자료 생성과 재채점

CLI는 [74_evaluate_player_identity_ocr.py](../scripts/74_evaluate_player_identity_ocr.py)다.
저장소 루트에서 실행한다. 예측 생성에는 Windows 엔진과 고정된 로컬 이미지가 필요하다.

```bash
uv run --frozen python scripts/74_evaluate_player_identity_ocr.py predict
uv run --frozen python scripts/74_evaluate_player_identity_ocr.py score --verify-frames
uv run --frozen python scripts/74_evaluate_player_identity_ocr.py check --verify-frames
```

기본 입력은 PA6 평가셋이며 출력은 아래 두 파일이다.

- [원문 예측](results/mlb_p0/game_747139_player_identity_ocr_v1_predictions.json): `predict`가 생성한다.
- [채점 보고서](results/mlb_p0/game_747139_player_identity_ocr_v1_report.json): `score`가 생성하며,
  `check`는 다시 계산한 결과가 저장된 보고서와 같은지 검사한다.

`--evalset`, `--predictions`, `--report`로 경로를 지정할 수 있다. 사용자 평가셋으로 예측할 때는
별도 `--predictions`가 필요하다. 사용자 평가셋 또는 예측을 채점할 때도 별도 `--report`를
지정해야 하며 기본 PA6 산출물에 덮어쓰지 않는다.

`predict`는 입력 프레임의 영상 출처·재생 초·이미지 바이트 해시를 항상 검사한다.
`score`와 `check`는 Windows OCR 없이 저장된 예측을 다루며, `--verify-frames`를 추가하면
로컬 이미지 근거까지 다시 검사한다. 이 옵션 없이 통과한 재채점을 이미지 재검증이나 OCR 재실행으로
표현하지 않는다. 코드/자료 해시는 출처를 추적하기 위한 것이며 문자열의 의미가 맞음을 자동 보증하지 않는다.
