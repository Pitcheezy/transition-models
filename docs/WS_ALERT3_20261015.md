# WS-alert3 — 잘못된 감시 파일의 알림 대기 삭제 방지

이전 CLI는 `{ "state": { "events": [] } }`를 장애가 끝난 상태로 받아들였다.
이미 저장된 재알림 대기2개가 abandoned 처리되고 열린 장애 기억이 삭제되며 성공으로 종료되는 문제였다.
이제 알림 잠금·읽기·전송·저장 전에 필수 구조와 incident를 검사한다. 잘못된 입력은 종료2로 거부하며
기존 상태 파일을 바이트 그대로 보존한다. 정상 null 복구, 열린 장애 재시도, 개별 bad event 건너뛰기는 유지한다.

기준 main `5eae6e185ef584c396fd4bf5189dfa9717f52316`, 고정 코드 `a4932bbe2f152cce15fc7d05c933d792450cfdf2`.
[선점·합격 기준](https://github.com/Pitcheezy/transition-models/issues/3#issuecomment-6189380444),
[운영 설명](../ops/public-host/ALERTS.md), [검증 영수증](results/ops/ws_alert3_20261015.json).

- 새9검사: incident 오류9종, envelope/events 오류10종, 기존 대기/새 상태 보호, 정상 복구/재시도, 실제 CLI 종료1/2.
- 기존 알림36, 전체 Node232, 체크리스트8, 문법 검사 통과.
- 합성 임시 파일과 모의 transport만 사용했다. 전체 monitor 스키마/설정 fingerprint/출처나 실제 복구를 인증하지 않는다.
- 실제 알림·배포·팀원 저장소는 변경하지 않았다.
- 작성 GPT-6 계열(Codex, 정확한 세션 모델 id 미노출), 독립 검토 gpt-5.6-sol: 고정 커밋 검토와 집중9검사 PASS, 지적 없음.
- 기존 write/sync 실패의 임시 파일 잔류는 별도 후속 작업이다. 이번 입력 보호 변경과 구별한다.
