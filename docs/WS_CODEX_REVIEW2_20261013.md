| 이용 집계 | 요약 날짜가 보고 기간 일부만 포함해도 행이 한 개 이상 있으면 정상 전체 집계처럼 출력 | 관측된 수치는 보존하고 부분 집계와 미측정 범위를 명시 |
| 감시 집계 | 보고 기간 뒤의 최초 관측 하나로 과거 기간을 관측한 것처럼 표시 | 마지막 관측과 기간 내 실제 이벤트만 증거로 사용 |

| 계약 검증 | 오프라인 도구가 받은 JSON Schema의 HTTP 및 file `$ref`를 자동으로 읽으려 함 | 명시적인 오프라인 registry로 외부 참조 차단, 내부 `$defs`는 허용 |
| 보고서 입력 | 음수 활성 시간·잘못된 고정 선택값·범위 밖 날짜·중복 집계 행을 받아 부정확한 합계를 만듦 | 날짜·정수·선택값·그룹 유일성·합계 안전 범위 검증 |
| 감시 목록 밖 재시도 | 실패한 발생/복구 알림의 원본이 감시의 최근 100개 목록에서 밀려나면 저장된 pending이 있어도 재시도가 사라짐 | 저장된 pending에서 메시지를 다시 구성하고 발생→복구 순서·중복 제거·상한을 전송 전에 검사 |
| 알림 번호 경계 | 유효한 재분류 9,999번 또는 재알림 999,999번 이후 생성된 번호가 저장 키 형식과 충돌해 같은 열린 장애의 다음 실행도 중단됨 | 생성·검증 범위를 안전정수로 맞추고 절대 상한은 전송 전 명시적으로 거부; 구형 형식으로 표현할 수 없는 되돌리기도 거부 |

모든 재현은 합성 자료·mock 전송·로컬 파일을 사용한다. 외부 참조 회귀는 `urlopen`을 가로채 메모리의 `{}`를 반환하므로 실제 외부 접속이나 비밀 파일 읽기를 하지 않는다.
번호 경계 문제는 **전송 전** 예외이며 원본 상태는 보존됐다. 이 경우 중복 발송이 발생했다고 주장하지 않는다. 발생 가능성이 낮은 장기간 열린 장애의 경계 결함으로 분류했다.

## 호환성과 독립 검토

- 접근 쿠키는 v3으로 변경한다. v1/v2 쿠키는 새 코드에서 거부되며 사용자는 다시 로그인해야 한다. 코드 되돌리기도 v3 쿠키를 받아들이지 않으므로 재로그인이 필요하다.
- 알림 상태는 v1/v2를 v3으로 올린다. 원본 보존 뒤 되돌리기 출력을 별도 파일로 생성한다. 과거 형식으로 표현할 수 없는 대기열/파일 크기는 조용히 자르지 않고 거부한다. v1은 재분류를 지원하지 않아 해당 항목을 제외하며, 감시에서 밀려난 이벤트 재시도도 지원하지 않는다. 이전 형식에는 완전성 메타데이터가 없어 보고서에서 이력을 완전하다고 추정하지 않는다.
- 첫 보존 정책(1,000행/1MiB)은 2,307회 실제 저장·재읽기에서 통과했다. 감시 목록 밖 재시도를 보존하는 후속 정책(4,096행/8MiB)은 별도 경계·최대 입력 검사를 통과했으며 앞선 장시간 결과를 새 정책의 측정값으로 옮기지 않는다.
- 이번 작성 모델은 GPT-6 계열이다. 저장소의 다른 모델 검토 조건에 따라 `gpt-5.6-sol`을 별도 검토자로 선택했다. 최종 코드 `2ce3a70a142c592d1db06d242616669766e1a6f7`의 독립 판정은 **PASS, 남은 실행 가능 지적 없음**이다. 앞선 `e68c8a2` 및 `2fd915e` 검토와 후속 차이 검토를 합쳤으며, 알림 36/36을 독립 재실행했다.
- 독립 검토에서 확인한 집계 입력 검증, 대기열 보존, 번호 경계, 과거 원문 누락 경로를 수정·회귀로 남겼다. 최종 코드 이후 커밋은 검사 영수증·현재 상태 문서만 추가한다. PR의 최신 커밋별 CI 결과는 GitHub에서 확인한다.

로컬 재현에는 `TMPDIR=/private/tmp`를 사용한다. macOS 기본 임시 경로의 `/var` 심볼릭 링크는 도구의 링크 거부 정책에 걸린다. Worker/브라우저 검사는 localhost listen을 허용한 실행에서 수행한다. 샌드박스의 listen 거부를 제품 결함으로 세지 않는다.
