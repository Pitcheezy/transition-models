## 최종본에서 확인할 사항

1. **작성/검토 모델:** “Claude Opus / 별도 Claude 에이전트”만으로 다른 모델 여부를 알 수 없다.
   같은 모델이라고 단정하지 않는다. 정확한 모델 식별자와 검토 대상 전체 커밋·파일 SHA·지적/해결 기록을 확인한다.
   [규약5절](COLLABORATION_PROTOCOL.md)의 다른 모델 검토 조건을 별도 세션으로 대체하지 않는다.
2. **N23:** [앞선 CX40 기록](https://github.com/SongRoute/pitcheezy/issues/35#issuecomment-6258507452)은
   정상 시험 자료 준비 완료·강제 거부 구현 잔여라고 썼고, 최신 회신은 시험 자료 변경 대기라고 썼다.
   각 설명의 대상 파일/버전과 최종 남은 조건을 확인한다. 최신 설명이 무조건 잘못됐다고 단정하지 않는다.
   최종본에서 잘못된 토큰의 실패 단계·종료 상태·요청 발생 여부·자격 노출 여부·요청 예산/정리 영향을 확인한다.
   “안전한 실패” 보고로 네트워크0회나 합격을 추정하지 않는다. 경고 수용이나 시험 자료 변경을 우리가 임의 결정하지 않는다.
3. **전달 날짜:** 원문은 “10/22(수)”다. 2026-10-22는 목요일이므로 날짜·요일·시간대를 확인한다.
   원문을 보존하고 10/21 또는10/22로 일방 확정하지 않는다. 이는 전달 목표이며 실제 시험 창이 아니다.
4. **동결 이후 범위:** 규약은10/21 이후 고장 수리만 허용한다. 10/21 화면 작업이 고장 수리,
   고정본 포장/재등록 또는 새 기능인지 확인한다. 위반을 단정하거나 일정 예외를 자동 승인하지 않는다.

## 파일이 오면 진행할 순서

각 단계는 별도 상태로 기록한다. 한 단계 완료가 다음 단계의 승인이나 성공을 뜻하지 않는다.

1. **보고 접수 — 완료:** 위 회신과 라벨을 확인했다. 원문 SHA는 GitHub API의 body 문자열을 UTF-8로 인코딩한 기준이다.
   ZIP이나 소스 파일의 해시를 대신하지 않는다.
2. **최종 파일 접수 — 대기:** 원본 ZIP/파일 크기·SHA-256, 경로/파일 목록·manifest를 먼저 확인한다.
   압축 해제 전 절대경로/상위경로 이탈·링크·예상 밖 항목을 확인하고 원본은 보존한다. 기존 파일 위에 덮어쓰지 않는다.
   실행본·등록서·재현 명령·검토 결과·모델 식별자·남은 조건을 같은 최종본에 연결한다.
   runner/wrapper/client의 전체 커밋과 고정 해시를 구분한다. `host_rehearsal.py`와 `onekey_wrapper.py`를 같은 파일로 보지 않는다.
   원본 바이트 SHA가 수신 기준이며 줄바꿈 정규화 SHA는 보조 비교다. 공개 파일 계약 버전과 의도 스펙 버전도 구분한다.
3. **내용과 지원 환경 확인 — 대기:** 기본 업로드OFF, 주소/자격 포함 여부, 실행 명령의 통신/쓰기 부작용과
   고정 의존성을 먼저 검토한다. 비밀이 있으면 공개 출력·커밋하지 않고 담당자에게 비공개 조치를 요청한다.
   받은 명령을 검토 없이 실행하지 않는다. 최종본의 검토 범위와 전달 파일이 다르면 해당 부분을 다시 검토한다.
4. **허용된 로컬 검증 — 대기:** 지원되는 정적/오프라인 검사부터 수행하고 필요하면 비밀 없는 격리 loopback만 사용한다.
   통과/실패/실행불가를 구분하며14개라는 숫자에 맞추려고 자료를 바꾸지 않는다.
   이전 Windows `fcntl` 제약은 새 전달본의 지원 근거가 없는 한 남는다. 우회 구현을 원래 실행본 성공이라고 쓰지 않는다.
   이 단계는 상대 레포·Mac·실서버 접근을 허용하지 않는다. 모델 가중치 이식을 새 선행 조건으로 만들지 않는다.
5. **실제 연결 준비/승인 — 별도 대기:** [WS-stage5 실행안](WS_STAGE5_READINESS_20261018.md)에
   최종 고정 파일·배포 출처, 시험 창(KST/UTC), 대상 자원, 단일writer, 자격 발급/만료/회수,
   긴급 연락/응답 시간, 중단·복구 책임과 전체 요청 원장을 대조한다.
   18/20/21회는 포함 단계가 다른 부분합이다. 사전점검·관리 요청·재시도·실패 정리까지 포함한 한도는 합의해야 한다.
   만료와 실제 자격 폐기를 구분하며 기존 본인 시험 승인을 Song 접속/배포/실경기로 확대하지 않는다.

원본에 없거나 실행하지 못한 항목은 대기로 유지한다. 받은 자료의 식별·검토가 끝나도 #38 전체 합격 기준과
남은 조건을 확인하기 전에는 이슈를 닫지 않는다. 이 수신 체크리스트를 새 공개 스키마 요구로 보내지 않는다.
