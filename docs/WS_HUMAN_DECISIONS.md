## 10/18 비공개 v4.2 실제 수신과 회신 준비

사용자가 비공개 v4.2 ZIP을 첨부했다. 원본 공개 금지 요청을 따르며 수신·로컬검증·우리 코드 수정·반환자료 구성만 진행한다. [검증·남은 결정](WS_PARTNER_V42_20261018.md). 상대 #18 댓글로 우리 기존 ZIP 수신/검증 보고도 확인됐다. 아래 미수신/전달경로 대기는 이 이전의 기록이다.
공동 시험창·단일writer·발급/회수/실제접속·긴급연락은 아직 확정되지 않았다. 17회 runner에 로그인/회수 확인을 더하면19회이므로 전체18회 조건과의 조율이 필요하다. 이번 회신과 반환 ZIP은 준비만 하며 게시/새 공개링크/자격발급/배포는 실행하지 않는다.

## 10/18 ZIP도 함께 공개 게시 — 이번 우리 팩만

사용자가 ZIP을 함께 올리라고 직접 지시했다. 검증한 우리 소스 전달팩 한 건을 GitHub 검토용 pre-release asset으로 공개하고 #18에 링크를 게시했다. [범위·실제 다운로드 검증](WS_PUBLIC_HANDOFF_20261018.md).
기존 비공개 전달 제안 중 **이 우리 팩의 전송 경로**를 바꾼 결정이다. Song의 비공개 소스/영상·실주소·자격 공개, 실제 접속 대상·비용·배포·실경기를 승인한 것이 아니다. 상대 실제 수신은 미확인으로 유지한다.

## 10/18 같은 형식으로 전달 — 우리 측 준비/회신 범위

사용자가 “형이 제공하는 방식 그대로 우리도 전달하자”와 다음 작업 진행을 지시했다.
우리 고정 소스·안내·파일별 SHA·로컬 검증/한계를 비공개 ZIP으로 준비하고, 기존 COLLAB-001 #18에
이 전달 안내 한 건을 남기는 범위로 적용한다. 이전 두 회신의 권한을 재사용한 것이 아니다.
ZIP은 본인에게 준비해 기존 사람 간 비공개 대화로 전달하도록 하며 실제 상대 수신은 별도 확인한다.
구체 채널명/상대 수신 확인을 새로 얻은 것은 아니다. 새로운 공유 계정·공개 ZIP 링크·인증 값 전달은 하지 않는다.
실제 Song 시험 접속, 자격 발급, 시험 창, 배포/실경기/추가 비용 승인은 여전히 별도다.
[전달 안내](handoff/ws_host_20261018/START_HERE.md). 게시 결과는 최종 전달 영수증에서 확인한다.

## 10/17 새 Song 연결 준비 요청

[새 mail](https://github.com/Pitcheezy/transition-models/issues/18#issuecomment-6212003299)을 수신했다. 로컬 후보 준비 보고와 소스/빌드 실제 수신은 다르다. [구체 준비안](WS_PARTNER_TRIAL_PREPARATION_20261017.md)·[회신 원문](mail_drafts/COLLAB-001-trial-preparation-20261017.md)을 작성했고, 사용자가 이 초안만 새 #18 댓글로 게시하도록 승인해 [1회 게시](https://github.com/Pitcheezy/transition-models/issues/18#issuecomment-6218521394)·원격 대조를 완료했다.

지금 필요한 결정은 **후속 ZIP의 비공개 전달 방법 확정**이다. 새 회신 한 건의 게시 승인은 완료했으며, 발신 승인 자체가 전달 채널/접속 허용 승인까지 의미하지 않는다. 제안은 기존 사람 간 비공개 전달 후 우리 담당자가 이 작업 채팅에 첨부하는 방식이며, 새로운 공유 계정/공개 링크는 만들지 않는다. 아직 확정하지 않았다.

실제 Song 시험 허용은 ZIP 수신/검증 뒤 고정 후보와 함께 별도 확인한다. 기존 본인만 시험 승인은 Song 접속까지 포함하지 않는다. 제안 예산은 한 키·원문2KiB·runner18요청·120초이며 현재 bearer에는 서버측 경기 키 범위/자동 만료가 없다. 토글/자격 회수 담당·단일 writer·시작/종료 창과 이 제약을 포함한 실행안이 필요하다. 지금 자격을 발급/전달하거나 시험을 시작하지 않는다.

WS-publish2에서 [정확한 키·만료 제한 후보](WS_PUBLISH_SCOPE_20261017.md)를 로컬로 준비했다. 위 “현재 bearer에 제한 없음”은 마지막 실제 배포 기준이며 새 후보는 미배포다. 실제 사용 전 고정 후보 검토 결과와 제한 활성화·종료 후 digest 폐기 절차를 실행안에 포함하고 접속 범위 승인을 확인한다.

## 첫 준비를 여는 네 항목 — 답변 완료 (아래는 기록 양식)

- **계정과 담당:** 사용할 호스팅 계정의 소유 역할, 실제 설정을 할 사람. 예: 본인 소유 Cloudflare 계정 / 본인. 기존 도메인 구매를 이 신규 호스팅 계정·비용 승인으로 간주하지 않는다.
- **첫 접속 범위:** 우리 담당자만 / 우리와 Song / 정한 초대 인원 중 선택. 별도 비공개 시험 환경부터 할지 정한다. 일반 공개나 기존 사이트 교체는 별도 결정이다.
- **비용:** 비용 발생 불가 또는 허용할 월간 USD 상한과 재확인 기준. 예상 비용은 선택한 부하·현행 가격을 다시 확인해 제시하며, 상한 승인을 자동 과금 차단 기능으로 설명하지 않는다.
- **이용 기록·피드백:** 각각 OFF 유지 또는 ON 준비. OFF를 선택하면 이번 비공개 시험에는 수집하지 않고, 수집 동의·보관일 결정은 활성화 전에 한다. OFF도 공개 범위·비용·실경기 연결 승인과 별개다.

답변용 형식(값은 예시로 미리 채우지 않음):

```text
계정 소유 역할 / 설정 담당:
첫 시험 접속 대상 / 기존 사이트와 분리 여부:
월간 USD 예산 / 재확인할 비용 기준:
이용 기록 OFF 또는 ON 준비 / 피드백 OFF 또는 ON 준비:
```

이 네 답이 오면 **승인된 범위의 실제 계정 준비 계획·고정 배포 도구/버전·설정 후보**를 구체화할 수 있다.
가격과 계정 권한을 확인하기 전에 비용이나 자원을 자동 만들지 않는다. 실제 배포할 고정 후보와 예상 비용·권한 변경을 검토할 수 있게 준비한 다음,
사용자가 승인한 실행 범위를 확인한다. 이 문서 작성만으로 배포 승인이 생기지 않는다.

## 계정 없이 먼저 풀 수 있는 한 항목

- **실제 알림 채널 종류:** 사용할 채널 이름을 정하면 그 채널의 transport 구현·모의 검사를 준비할 수 있다. 사용자는 이메일을 희망한다고 답했다. 발송 제공자·인증·실제 발송 승인은 미정이다.
  채널 선택은 실제 발송 승인이나 수신자 확인이 아니다. 연락처/토큰은 비공개이며 양쪽 수신·응답 시간은 따로 확인한다.

```text
알림 채널 종류:
양쪽 수신/응답 시간 합의 여부:
```

이메일 후보로 Cloudflare Email Service를 조사했다(10/15 공식 문서). 인증된 수신 주소로 보내는 메일은 모든 플랜에서 무료이며 Worker 실행 요금은 별도다.
실제 계정 기능·발송 도메인 DNS·수신 주소 인증은 확인하지 않았고 설정하지 않았다. Gmail은 수신 주소로 쓰므로 Gmail 비밀번호를 저장하거나 받지 않는다.
이 후보 조사만으로 제공자를 최종 선택하거나 도메인 설정·메일 발송을 승인하지 않는다.
[공식 요금](https://developers.cloudflare.com/email-service/platform/pricing/) · [발송 설정 조건](https://developers.cloudflare.com/email-service/get-started/send-emails/).

## 공개·수집·실경기 전에 별도로 결정할 것

- **10/20까지 연락과 응답 시간:** 우리/Song 담당자의 비공개 연락 수단과 시간대. 우리 쪽 예약 등록은 Song의 일일 확인 수행 근거가 아니다.
- **수집을 켤 경우:** 이용 기록과 피드백 각각의 동의 안내·보관일·일별 저장 상한·열람/삭제 담당. 원시 자료·접속 주소는 공개 이슈에 올리지 않는다.
- **긴급 안내와 복구:** 양쪽 담당 사람이 즉시 안내로 바꿀 수 있다는 원칙은 이미 합의됐다. 남은 것은 실제 운영자 권한·비공개 조작 경로·문구·다시 공개할 담당이다. AI의 실제 조작은 승인된 위임 범위만 따른다.
- **실경기/기존 사이트:** 연결할 경기·시간·범위, 기존 Sites/DNS를 바꿀지, 실제 운영 재개 승인. 비공개 시험을 일반 공개로 확대하지 않는다.
- **발신:** [10/15 회신](https://github.com/Pitcheezy/transition-models/issues/18#issuecomment-6190443556)과 [10/17 후속 회신](https://github.com/Pitcheezy/transition-models/issues/18#issuecomment-6218521394)을 각각 별도 승인 후 한 번씩 게시했다. 이 두 건 밖의 mail 생성·자동 경기 보고·추가 메시지는 별도 승인 범위다.
- **10/21 이후:** 기능 추가 대신 고장 수리만 한다. 날짜가 도래했다고 출시 승인으로 바꾸지 않는다.

## 결정 기록과 재개 방법

결정마다 `항목 / 사람이 정한 값 / 승인 범위 / 확인 시각 / 대화 또는 이슈 근거 / 남은 조건`을 남긴다.
비공개 결정 근거는 공개 파일에 복사하지 않고 승인 여부만 기록한다. 현재 사용자 답변(2026-10-15, 이 채팅)에 따른 비밀 없는 기록은 다음과 같다.

- 계정 소유 역할: 본인 Cloudflare 계정. [WS-stage2](WS_ACCOUNT_READINESS_20261015.md)에서 로그인 계정의 Free 플랜·전체 관리자·D1 없음·R2 가입 전·대상 zone Active를 읽기 전용으로 확인했다. 이후 R2만 명시 승인 후 활성화했고 버킷0/표시 사용료0을 확인했다.
- 시험 접속 대상: 본인. 기존 공개 사이트 변경·일반 공개·Song 접근까지 승인한 것이 아니다.
- 월 예산: 월 $10 이내로 준비. 유료 가입·청구 발생 승인이나 자동 과금 상한이 아니다. 실제 계정 포함량·세금/제외 항목을 확인해 초과 우려가 있으면 실행 전에 재확인한다.
- 이용 기록·피드백: 첫 시험은 둘 다 OFF. 사용자 행동을 새로 수집하지 않는다. 보관일/동의 정책은 향후 ON 전에 정한다.
- 알림: 이메일 희망, 개인 수신 정보는 공개 파일에 기록하지 않는다. 발송 제공자·인증·실제 발송·Song 수신자는 미정이다.
- COLLAB-001: 이 파일에 연결한 10/15 회신의 구분선 안 본문만 1회 게시 승인, [게시·원격 대조 완료](https://github.com/Pitcheezy/transition-models/issues/18#issuecomment-6190443556). 이후 10/17 후속 회신도 별도 승인·게시 완료(위 최신 기록). 이 두 건 밖의 글은 미승인.
- R2 가입: 무료 포함량 초과 과금·자동 갱신·약관 동의를 포함해 별도 명시 승인 후 활성화 완료. 당시 버킷은0개였고, WS-stage4에서 신규 시험 버킷1개를 만들었다.
- 10/16 실제 시험 승인: 본인 전용 신규 Worker/R2/D1 각1개, 당일 만료 토큰과 네 비밀, 별도 접근 제한 시험 경로, 합성 업로드·철회·복구를 명시 승인받아 완료했다. [결과](WS_STAGE4_CLOUD_TRIAL_20261016.md). 최종 gateON/읽기·업로드·수집·피드백OFF. 다른 유료 가입·일반 공개·기존 사이트 전환·추가 접속자는 미승인이다.

이용 기록은 동의한 브라우저 세션 수와 화면 활성 시간이며 고유 사람 수가 아니다. 피드백은 도움됨/불명확/문제 있음과 선택 범주이며 자유문·연락처를 받지 않는다. 자세한 저장·동의·보관 범위는 [TELEMETRY](../ops/public-host/TELEMETRY.md)를 따른다.

완성된 공개 빌드와 고정 출처가 오면 [패키지 검사](../ops/public-host/RELEASE.md) → [설정 검사](../ops/public-host/CONFIG_CHECK.md)를 사용한다.
두 검사는 계정/배포 기능이 없고 `deployable=false`다. [운영 절차](../ops/public-host/RUNBOOK.md)의 실제 실행용 CLI는 WS-stage2에서 별도 폴더에 4.151.0으로 고정했다. 본인 전용 합성 자원·시험 배포는 WS-stage4에서 완료했다. Song 최종 화면·실경기·일반 공개는 남았다.
지금 임의 배포 명령을 채워 실행하지 않는다. 선택한 다음 작업에 필요한 결정과 입력이 준비되면 짧은 다음 작업을 우리 board에 먼저 등록한다. 알림 채널의 모의 구현이나 계정 준비 계획을 위해 모든 Song 전달물을 기다리지는 않는다.

## 월 예산을 고르기 위한 설명 — 2026-10-15 조회

Cloudflare 상품 가격과 우리에게 허용할 예산 상한은 다르다. Workers Free는 하루10만 요청·호출당 CPU10ms 한도, Paid는 월 최소$5와 포함량 초과 종량제다.
R2 Standard는 월10GB-month·쓰기100만·읽기1천만 무료 구간, D1은 별도 읽기/쓰기/저장 포함량이 있다. 현재 사용량/상품 상태는 WS-stage2에서 확인했다. 실제 시험 CPU·미래 청구액은 미측정이다.

- **추가 비용 $0:** 무료 구간에서 가능한지 확인한다. CPU/요청 한도로 시험이 제한될 수 있고 무료 보장을 하지 않는다.
- **월 $10 준비 예산 — 사용자 선택:** 본인만 시험하는 작은 규모로 구체화한다. 현재 Free 유지가 우선안이며 $5 기본요금은 Paid 전환 시에만 적용된다. 사용량·메일·세금은 별도 확인한다. R2만 별도 승인으로 활성화했고 Paid 전환은 미승인이다.
- **월 $30 예산 후보:** 다음 제한 운영 검토용 여유 범위다. 현재 본인 시험에 이 금액을 쓸 필요가 확인된 것은 아니다.

$10/$30은 Cloudflare 요금제 이름이나 고정 청구액이 아니다. 정한 예산은 자동 과금 차단 장치도 아니다. 실제 계정 준비 전 가격·설정·예상비용을 다시 맞춘다.
기존 비용 산정기는 10/12 가격 스냅샷으로 실행했다. 7경기×3시간·평균100명·5초마다JSON2개·CPU5ms 가정에서는 포함량이 남으면$5.00, 이미 소진됐다는 민감도에서는$12.19다.
평균1,000명 가정은$21.26/$32.98이다. 실제 접속량·CPU 측정이 아니며, 도메인·세금·이메일·로그·가정 밖 요청은 제외한다. 본인시험의 실청구 예상값으로 대입하지 않는다.
