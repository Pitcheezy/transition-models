**결과: STOPPED/미완. 서버 종료 설정은 확인했고 오늘 옛 발행 토큰401·OFF 후503은 실측하지 않았다.**
이 문서는 PR75 준비 문서 `5ad28ed6556629ceee22991c9692b5369010cbfc` 이후 실제 기록을 정리한다.
[구조화 기록](results/ops/ws_joint_trial_closeout_20261026.json)과 비공개 원본 SHA로 출처를 구분한다.
이번 정리 작업에서는 Cloudflare 변경·추가 서비스 요청·새 자격 발급·Song 코드 접근을 하지 않았다.

## 1. 무엇을 실행했나

- 범위는 가짜 경기 한 키의 합성 전송 시험 A다. 실제 경기 화면 연결 B·일반 공개·정책 성능 시험이 아니다.
- Song이 기존 final2/v4.4 `000e4ba0d83bb81fee8db82539e67c7ab0e7d0b3`를 지정했고, 그 화면을 시험 호스트에 적용했다. 오늘 A에는 새 v7/v4.5 ZIP이 필수 입력이 아니었다. 새 최종 화면의 안내 철회 결함 해결까지 확인했다는 뜻은 아니다.
- 호스트 runtime은 `e9b362b75d6d4768c552740bfc6e0124872805e1`, 원격 worker.js 54,114bytes, SHA `3312fbff2dac2a22b32e474392ee7eb107663c79e9749781810a681e5ee07cfd`다.
- 화면 index.html SHA는 `0caf5b837ef2dfb5c6890d17e01ccf8761dd034949ee1e3e6bb3070a7f511428`이다. 배포 버전과 Git 소스 커밋은 다른 식별자다.
- 본시험 적용 버전은 `44d6204b-e3e9-4b5a-aaf1-c831acf6de58`. 업로드/읽기 ON, 정확한 단일 키 scope, 절대 만료 `2026-10-26T12:50:00.000Z`(21:50 KST), 접근문 ON·수집/피드백 OFF였다.
- 사전 홈 HEAD는 Cookie 포함·User-Agent 없음으로 200. 클라이언트 시각은 Song 보고, 저장 서버 이벤트와 대조한 기록은 우리 관측이다. 루트 응답의 HIT와 발행 경로 캐시는 구별한다.
- 본시험 시작은 **21:40:12 KST**(Song이21:40:50에서 정정), 5.7초·본시험9요청+범위 밖1요청은 Song 보고다. 서버 저장 이벤트8건은 범위 밖1건을 포함하므로 미대조 요청은2건이다.
- 마지막 HEAD 응답을 실행본이 확정하지 못해 재시도 없이 중단했다. 전체 클라이언트 원장·전체 PRECONDITIONS SHA는 아직 받지 못했다. SHA 앞자리만으로 파일 식별을 완료하지 않는다.

## 2. 확인한 것과 확인하지 않은 것

서버에서 범위 밖 HEAD403, 키 미존재 HEAD404, PUT200, 공개 GET200, DELETE200와 후속 HEAD200 이벤트를 확인했다. 마지막 서버 HEAD가 클라이언트의 어느 순번인지 원장 없이 확정하지 않는다. 저장 로그8건과 Song10요청의 차이는 **미대조**이며 Worker 미도달이나 캐시 응답의 증명이 아니다.

만료 뒤 HEAD403 세 건은 **21:50:21.470 / 21:50:32.693 / 21:50:47.914 KST**이며 모두 본시험 버전44d6204b와 일치한다. 후속3회가 모두 만료 검사에 사용되어 옛 토큰401과 OFF503의 요청 예산이 남지 않았다. 우리 측이 임의로 추가 호출하지 않았다. 10/25 본인 시험의401/503을 오늘 공동시험 합격으로 가져오지 않는다.

## 3. 종료는 완료했나

관리 API 적용과 설정 대조로 다음 순서를 확인했다. 아래는 **실제21:57 처리 기록**이며 다음 창에서 실행할 명령이 아니다.

1. 발행 digest 교체 → `1bb72964-442c-4509-9e60-2a57bf3c615d`.
2. 업로드·자료 읽기 OFF → `7da114b9-780c-481c-b6a6-6e80786d4466`.
3. scope·expiry 제거 → `6bae37b3-c562-432d-8175-7ee8c827f21e`.
4. 오늘 관람 자격 제거·본인 복구용 자격 보존 → **최종 `207c638d-5040-4ec3-ad92-0e2525f0272c`**.

접근문 ON·수집/피드백 OFF·원격 runtime 바이트 불변을 확인했다. 종료 처리 중 서비스 요청0건이다. 따라서 자격 회수 및OFF **설정 적용은 확인**, 그 뒤 HTTP401/503 **응답은 미측정**이다. 해당 비공개 폴더의 오늘 자격 사본7개는 폐기했으며 저장매체 보안 삭제나 상대 사본 폐기까지 주장하지 않는다.

사용자는 긴 종료 메시지는 아직 보내지 않고 다음 날 다시 하기로 이야기했다고 알려왔다. 우리 종료 기록과 상대에게 전달 완료한 사실은 구별한다. 다음 창 전에는 최종 종료 상태를 짧게 공유하고 상대 사본 폐기를 확인하는 것이 필요하다. 이 작업에서 상대에게 새 메시지를 보내지 않았다.

## 4. 캐시 문제라고 확정할 수 있나

**아직 아니다.** 오늘 조회한 Cache Rules·Cache Response Rules·Page Rules는0개이며 새 캐시 규칙이나 purge를 적용하지 않았다. Browser Cache TTL4시간이라는 설정만으로 발행 인증 경로가 캐시됐다고 결론내리지 않는다.

고정 runtime e9b362b의 근거:

- [gateway.mjs](../ops/public-host/gateway.mjs)의 응답 함수는 발행 성공/오류에 `Cache-Control: no-store`, `CDN-Cache-Control: no-store`, `Age: 0`, `Date`를 부여한다. 발행 경로는 정적 ASSETS보다 먼저 처리한다.
- **비공개 `/_publish/v1/game/<key>.json` HEAD는 삭제 뒤에도200일 수 있다.** 삭제표식 객체의 `X-Publish-Deleted: true`와 새ETag를 반환한다. **공개 `/v1/game/<key>.json` HEAD는404**다. 상태200 하나만으로 삭제 실패나 캐시를 판정하지 않는다.
- [access.mjs](../ops/public-host/access.mjs)의 `privatizeHeaders`는 ASSETS 응답 헤더를 복사한다. 자산의 HIT 표기가 인증 검사 뒤 응답에 남을 수 있다. 이것이 오늘HIT의 실제 원인이었는지는 미확인이다.
- [기존 단위 검사](../ops/public-host/tests/worker.test.mjs)도 삭제표식200/공개404를 검증한다. 이번에는 private HEAD 오류·헤더와 실제 로컬 R2 상태 전환을 보완한다. **로컬 통과는 Cloudflare 실제 캐시 경로 통과가 아니다.**

원장을 받으면 시각·정확한 공개/비공개 경로·상태·ETag·X-Publish-Deleted·CF-Ray·CF-Cache-Status·Age·Date를 허용목록으로 대조한다. Authorization·Cookie·Set-Cookie는 공유 진단 자료에 넣지 않는다. 기록하지 않았던 헤더는 나중에 복원할 수 없으므로 미확인으로 남긴다.

## 5. 우리 쪽에 부족했던 점

**확인된 문서 오류와 실제 장애 원인을 분리한다.** 아래 오류가 오늘 중단의 직접 원인이었다는 근거는 없다.

- 정상 종료 절차가 업로드OFF 뒤401을 검사하도록 되어 있었다. OFF는503이 우선이므로 정상은 **만료403 → digest교체 →401 →OFF →503**이어야 한다. 긴급은OFF가 먼저이고401은 미검증으로 남긴다. 실제 오늘 종료 순서는 올바르게 처리했다.
- 관람 자격이 B에만 필요하다고 썼지만, A의 공개JSON GET에도 Cookie가 필요했다. 시험 이름이 아니라 실제 호출 경로로 자격을 정해야 한다.
- 창 전체 버전이 같아야 한다는 문구는 정상 자격 회수·OFF 설정의 버전 변경과 충돌했다. **본시험 구간 고정 + 종료 단계별 버전 변화 기록**으로 바꾼다.
- 후속3회의 총량만 있고 **만료1·회수1·OFF1**의 단계별 배정과 다음 단계 신호가 없었다. 사전 요청 수와 주체도 문서/원장 간 달랐다. 새 원장은 각 요청을 한 행으로 펼치고 상한·소유자·단계를 양쪽이 확인해야 실행 가능하도록 한다.
- Claude 준비 문서의20:35 HOLD와 Codex의 이후 실제 설정·시험 결과가 하나의 최신 인계로 모이지 않았다. 준비 완료, 활성화 완료, 시험 합격을 따로 표시해야 한다.

사용자는 로그인·등록·승인·상대와 연락을 수행했다. digest나 HTTP 상태를 몰랐던 것을 사용자 과실로 돌릴 일이 아니다. AI가 대상 서버·켜지는 기능·종료 시각·필요한 사람 결정만 쉬운 말로 제시했어야 한다. 앞으로 사람에게 필요한 일은 **같은 시험 창/범위 확인, 비공개 전달, 시작·중단 의사 전달, 종료 확인 공유**다.

공동으로 보완할 것은 요청별 시각·Ray·허용 헤더 기록과 후속 예산 배정이다. 실행본 내부 수정은 Song 담당이고 우리가 대신 수정하지 않는다. 전체 원장 미수신·일부 요청 정보 미확인 때문에 현재2건을 확정하지 못하지만, 그것만으로 호스트가 정상이라고도 단정하지 않는다.

## 6. 다음 창의 짧은 순서

“새 키·쿠키·발행 토큰으로 준비”는 **다음에 합의한 시험 직전에 새것을 마련한다**는 뜻이다. 지금 다시 켜거나 시험을 즉시 재개하라는 뜻이 아니다. 너무 일찍 Cookie를 만들면 실제 시작 전에 만료될 수 있다.

1. **지금 우리 쪽:** 종료 영수증/문서 정정·로컬 응답 검사. 서버OFF 유지. 원장 수신 후 대조할 항목을 준비한다.
2. **Song 자료 수신:** 클라이언트 원장·전체 PRECONDITIONS SHA, 다음 실행본의 고정 파일·검토 근거·요청 순서. 기존 파일을 다시 선택해도 무엇을 쓸지 명시한다.
3. **함께 결정:** A만인지, 시작/종료/만료, 단일writer, 카톡 중단 신호, 각 요청의 소유자·한도. [원장v2](results/ops/ws_trial_day_ledger_template_20261026_v2.json)는 미작성 값이 있어 지금 실행할 수 없다.
4. **창 직전:** 사용하지 않은 키(키+1도 확인), 새 발행/관람 자격, 만료 여유≥180초, 고정 화면·runtime·설정 적용 영수증. 발급/등록 주체는 승인된 실제 도구 경로에 따라 정한다. 비밀을 공개 이슈에 싣지 않는다.
5. **양쪽GO 이후:** 원장의 사전 접속·범위 검사·본시험만 수행한다. 알려지지 않은 응답이나 초과 시STOP, 임의 재시도 없음.
6. **정상 완료 후속은 한 번씩:** 만료403 1회 → 우리digest교체 확인 신호 → 옛Bearer401 1회 → 우리업로드/읽기OFF 확인 신호 →503 1회 →scope/expiry 제거 →오늘관람 자격 회수. 본시험STOP 뒤에는 자동 진행하지 않고, 양쪽이 합의한 후속 범위·남은 예산·단계별 신호가 있을 때만 후속한다. 관람 회수 응답을 측정하려면 별도 사전 예산이 있어야 한다. 정리 동작 자체는 검증 예산 소진을 이유로 미루지 않는다.
7. **긴급 또는 예산소진:** 즉시 필요한 차단·회수를 끝내고 미검증 항목을 남긴다.401을 보려고 다시 켜지 않는다. 다음창 승인 없이 요청 수를 늘리지 않는다.

본시험 중 알려진 삭제표식 HEAD200은 `X-Publish-Deleted:true`와 삭제ETag까지 맞아야 정상이다. 필수 헤더가 미확인이라면 안전하게 중단하는 동작은 유지한다. 별도 B의 최신화면/안내철회, 기존 안내로그12/13,11월부하·요금제 과제는 이번 시험으로 완료하지 않는다.

## 7. 재현·검토

이번 변경은 문서·검사뿐이며 운영5파일의 Git blob과 고정 runtime은 불변이다. 실행 명령·최종 결과는 [정리 영수증](results/ops/ws_trial3_validation_20261026.json)에 기록한다. 체크리스트·링크·JSON과 필요한 로컬 회귀만 검사한다. 실제 Cloudflare 추가 시험이나 다른 모델의 운영 코드 검토를 수행한 것으로 쓰지 않는다.
