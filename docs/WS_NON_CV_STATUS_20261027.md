# CV 제외 서비스 통합·운영 작업 현황 — 2026-10-27

이 문서는 10/26 공동시험과 10/27 협업 조회를 반영한 **우리 담당 비CV 작업 목록**이다. 새 서버 시험을 실행한 기록이 아니다. 기술 상태는 고정 근거를 따르며 현재 계정 상태를 재조회하지 않았다. 완료율 대신 구현·실측·대기를 구분한다.

## 1. 교수님께 설명할 내용

> 저는 팀원이 만든 추천 모델과 발행기를 서비스에서 사용할 수 있도록 클라우드 호스팅, 데이터 수신, 접근 통제, 로그와 장애 대응을 맡았습니다. 10월 26일에는 팀원의 발행기와 제가 준비한 실제 클라우드 서버를 연결해서 가짜 경기 자료의 업로드·조회·삭제 요청 수락, 허용 범위 밖 요청 차단과 만료 차단을 확인했습니다. 마지막 응답과 일부 로그의 대응이 명확하지 않아 전체 시험은 미완료로 남겼고, 시험 권한을 회수하고 업로드·자료 읽기를 껐습니다. 다음은 요청 기록을 맞춰 원인을 확인하고, 회수 응답까지 포함한 통합시험을 마무리하는 것입니다.

- 쉽게 말하면: **합성 발행 자료를 실제 서버에 안전하게 전달하고, 문제가 생기면 멈추고 접근을 회수할 수 있는지 함께 시험했다.**
- 전공자에게는: **독립 발행기와 클라우드 수신기의 계약 기반 통합시험, 키 범위·만료·권한 회수와 요청 로그 대조를 수행했다.**
- 실제 클라우드에서 **합성 자료**를 시험했다. 실경기 공개 서비스, 모델 정확도, 실제 관람자 효과, 30~50명 동시접속 합격으로 설명하지 않는다.
- 팀원은 추천 모델·발행기·최종 관전 화면을, 우리는 호스팅·업로드 수신·접근 통제·운영 관측과 대응을 담당한다. 역할 근거는 [협업 규약](COLLABORATION_PROTOCOL.md)이다.

## 2. 어제 실제로 한 작업과 판정

근거: [10/26 종료 보고](WS_JOINT_TRIAL_CLOSEOUT_20261026.md), [구조화 영수증](results/ops/ws_joint_trial_closeout_20261026.json), [PR76](https://github.com/Pitcheezy/transition-models/pull/76).

1. **배포 대상 대조:** 우리 고정 runtime `e9b362b75d6d4768c552740bfc6e0124872805e1`의 원격 바이트를 확인하고, Song이 지정한 기존 final2/v4.4 `000e4ba0d83bb81fee8db82539e67c7ab0e7d0b3` 화면을 시험 호스트에 적용했다. 새 UI 후보의 연결 완료는 아니다.
2. **시험 환경 설정:** 가짜 경기 한 키, 절대 만료, 관람·발행 자격을 분리하고 제한된 창에서 업로드·읽기를 활성화했다. 접근문은 ON, 이용 기록·피드백은 OFF였다.
3. **기본 전송·제한 동작 확인:** 서버 기록에서 범위 밖 HEAD403, 미존재 HEAD404, PUT200, 공개 GET200, DELETE200 및 후속 HEAD200을 확인했다. 고정 runtime 설계상 DELETE는 물리 삭제가 아니라 삭제표식 저장이다. 당시 삭제표식 헤더·새 ETag와 요청 순번 대조는 남아 있다.
4. **실패 시 중단:** Song 보고상 21:40:12 KST부터 5.7초 동안 본시험 9요청을 보냈고 마지막 HEAD를 확정하지 못해 재시도 없이 중단했다. 범위 밖 1요청을 포함한 클라이언트 10건과 서버 저장 로그 8건 사이 **2건은 미대조**다. 마지막 서버 HEAD가 실행본의 어느 순번인지는 원장 없이 확정하지 않는다.
5. **만료 확인:** 21:50:21.470 / 32.693 / 47.914 KST의 HEAD403 세 건을 본시험 버전과 대조했다.
6. **종료 처리:** 발행 digest 교체 → 업로드·읽기 OFF → scope·expiry 제거 → 오늘 관람 자격 회수, 본인 복구 자격 보존을 관리 API 적용과 설정으로 확인했다. 최종 버전은 `207c638d-5040-4ec3-ad92-0e2525f0272c`다. 종료 중 추가 서비스 요청은 0건이다.

**전체 판정은 STOPPED/미완**이다. 후속 3회를 모두 만료 검사에 사용했으므로 그날 옛 발행 토큰401과 OFF 후503은 실측하지 않았다. 설정상 회수·OFF 완료와 HTTP 거부 응답 검증을 구별한다. 10/25 본인 시험의 성공을 10/26 공동시험 성공으로 옮겨 적지 않는다.

캐시 원인은 미확정이다. 고정 runtime의 설계상 비공개 발행 경로는 삭제표식·새 ETag와 함께 HEAD200을 반환할 수 있고, 공개 자료 경로는 HEAD404를 반환한다. 상태200이나 다른 경로의 HIT만으로 삭제 실패·인증 우회·캐시 장애를 단정하지 않는다.

## 4. 남은 작업 — 중복을 뺀 8묶음

이는 보고용 묶음이며 같은 크기의 작업 8개나 완료율을 뜻하지 않는다. CV·사람 미트 판독은 이 목록에서 제외한다.

1. **10/26 미대조 요청·원인 확인 — 우리 + Song 원장 필요**

2. **다음 한 키 합성시험 A 마무리 — 양쪽 함께**
   - 우리: 고정 배포·설정 영수증, 새 키/자격/만료, 서버 관측·차단·회수 담당.

3. **최신 관전 화면 인수·로컬 연결 — Song 자료 대기, 검증은 우리**

5. **감시·알림을 실제 운영으로 연결 — 구현 기반 있음, 사람 결정·양측 수신 필요**

## 5. 당장 할 일과 사용자 역할

- 우리 AI가 독립적으로 할 수 있는 일: 기존 증거·절차·인계 정합화, 수신 대조 항목 준비, 구체 결함이 있을 때 우리 코드의 로컬 검사. 동일 시험·포장을 반복하지 않는다.
- 다음 실질 입력: Song의 요청 원장/고정 실행 절차, 그리고 실제 연결에 채택할 화면 빌드와 검토 근거. 최신 UI 자료와 A 전송시험의 입력을 한 덩어리로 막지 않는다.
- 사용자가 할 일: 교수님께 위 범위로 설명하고, 비공개 전달물을 받으면 작업 채팅에 첨부하며, 다음 창·시작/중단·접근 범위를 형과 결정한다. 계정 관리 키를 형에게 전달할 필요는 없다.
- 종료 상태를 형에게 실제 전달했는지는 아직 확인되지 않았다. 사용자 대화상 긴 종료 메시지는 미발신이었으므로, 다음 시험 전 짧은 종료 상태 공유와 상대의 지난 시험 자격 사본 폐기를 확인한다. 이번 작업에서 대신 발신하지 않았다.
