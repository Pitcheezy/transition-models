2026-10-17 갱신. **우리 운영 기반은 본인 전용 합성 클라우드 시험까지 완료했다. 일반 공개·Song 화면/발행기·실경기 연결은 미완료다.**

## 새 연결 요청과 독립 운영 도구 — 2026-10-17

Song의 [새 요청](https://github.com/Pitcheezy/transition-models/issues/18#issuecomment-6212003299)은 로컬 후보 준비·비공개 전달 경로와 한 키/2KiB/18요청/120초 시험 조건 문의다. 실제 소스/빌드는 미수신이며 접속 확대는 미승인이다. 후속 회신 초안 한 건은 사용자 별도 승인으로 [게시](https://github.com/Pitcheezy/transition-models/issues/18#issuecomment-6218521394)·원문 대조했다. [준비안·기존 bearer 범위/자동 만료 부재](WS_PARTNER_TRIAL_PREPARATION_20261017.md)와 회신 원문을 마련했다. Song10/16 상호조회 근거는 확인했지만 오늘 일일조회는 별도다.

기존 문서의 독립 작업 없음은10/15 당시 점검 결과다. 이후 실제 클라우드 시험과 새 연결 요청으로 안전한 운영자 CLI(WS-notice2), 유한 감시 반복 실행기(WS-monitor3)의 필요를 확인해 구현·검증했다. [운영 도구](WS_OPERATOR_TOOLS_20261017.md): 최종Node284·다른 모델 재검토PASS, 기간/중단 경계와 불가능한 날짜 결함을 고쳤다. 이 작업은 실제 접근 허용·배포·상시 설치·메일 발송이 아니다.

## 본인 전용 합성 실자원 시험 완료 — WS-stage4

[결과](WS_STAGE4_CLOUD_TRIAL_20261016.md)·[영수증](results/ops/ws_stage4_20261016.json). 사용자 구체 승인 뒤 신규 Worker/private R2/D1과 접근 제한 시험 주소를 만들고 실제 HTTPS88요청(초기 실패12포함)을 검사했다. Cloudflare 압축이 ETag를 weak로 바꾸는 결함을 고쳐 고정 host `87168d7`을 gpt-5.6-sol 검토 후 배포했다. 수정 후 조건부 발행/철회/복구/안내 왕복36요청과 최종OFF16요청 통과, 전체Node243통과. 최종 gateON·읽기/업로드/수집/피드백OFF·안내OFF, D1수집0행, 기존 사이트·팀원 코드·실경기 미변경. 공급자 집계CPU/저장량·실제1시간만료·cron·다중지역은 미측정이다. Song 최종 화면/발행기·사람 운영 결정·실경기 승인 대기는 그대로다. 아래 stage3 대기는 당시 준비 이력이다.

  정확한 바이트/SHA, 조건부 갱신·삭제 표식,404/no-store/Date/Age.
- [업로드 제한](../ops/public-host/UPLOAD_LIMITS.md) ·
  [단일 파일 전송기](../ops/public-host/PUBLISHER.md): 기본 dry-run,
  같은 바이트·ETag 재시도, 저장 여부 불명과 충돌 구분. 다중 파일 원자성/경기 스키마 검증은 미구현.
- [수집/위젯](../ops/public-host/TELEMETRY.md): 별도 동의·피드백 토글,
  메모리 ID·활성 시간, private D1, 중복/역순·당일 상한·집계·만료 정리.
  제한기 boolean true만 허용한다. 실제 사용자 수집은 켜지 않았다.
- [배포 패키지](../ops/public-host/RELEASE.md): 양쪽 고정 커밋·파일 SHA를 넣는 결정적 ZIP/manifest.
  출처·권리·서비스 동작 인증이 아니며 deployable=false다.
- [설정 검사](../ops/public-host/CONFIG_CHECK.md): 파일 목록/경로/설정과 화면 보관 안내 대조.
  계정 자원과 secret 존재를 확인하는 도구는 아니다.
- [긴급 안내 스위치](../ops/public-host/NOTICE.md): 운영자 토큰 digest·조건부 쓰기·감사 기록으로 화면/asset/JSON/수집을
  503 안내로 전환하고 업로드는 유지. 로컬 검증과 WS-stage4 실제 합성 HTTPS 전환을 완료했다. 최종 공개 문구·양쪽 운영자 권한·다중 colo 지연은 별도다.
- [관람 접근 문](../ops/public-host/ACCESS.md): `ACCESS_GATE_ENABLED`·코드 digest·세션 비밀로 화면/asset/JSON/수집을 401로 막는 무상태 세션 쿠키.
  업로드·안내 인증과 분리, 같은 출처 전제. WS-stage4에서 본인 한정 실제 코드·HTTPS·노트북 브라우저 로그인까지 확인했다. 접속 대상 확대·Safari는 별도다.
- [감시](../ops/public-host/MONITORING.md): 단발 읽기·지정된 발행 시각·장애/복구 상태·안내 상태 구별(`notice_active`)·접근 문 구별(`access_gate_active`).
  현재 상시 스케줄과 외부 알림은 미연결이다.
- [경기별 운영 기록 초안](../ops/public-host/REPORT.md): 입력 JSON(D1 요약·감시 상태·안내 감사·알림 상태·조치·소스·명령)에서 이슈 초안을 생성.
  수집 OFF/자료 없음은 미측정이다. 새 스냅샷 입력은 빈 행도 미측정이며, 보존 행은 부분 UTC 날짜 집계다. 기존 일반 요약 입력의 0행 처리는 호환을 유지한다. 게시는 사람 승인 뒤 수동이며 실경기 수치는 미측정이다.
- [양쪽 알림 후보](../ops/public-host/ALERTS.md): 감시 이벤트 분류(발행 중단→Song 우선, 호스팅→우리 우선, 혼합→양쪽)·두 수신자·중복 억제·
  재알림·재시도를 mock transport로 검증. 실제 채널·연락처·발송은 사람 결정이며 모의 확인은 전달 확인이 아니다.
- [합성 리허설](../ops/public-host/REHEARSAL.md) ·
  [영속 재시작](../ops/public-host/LIFECYCLE.md): 실제 로컬 Worker/R2/D1,
  브라우저·충돌·철회/복원·키 교체·수집 OFF 정리. CDN/실계정 복원 성공은 아니다.
- [장애 대응](../ops/public-host/RUNBOOK.md) · [비용 산정](../ops/public-host/COST_PLAN.md):
  대응 절차와 날짜가 붙은 가격/부하 가정. 월 $10 이내 준비 범위는 사용자 결정이며 실제 비용·수용량은 미측정이다.

## 계정 없이 실행하는 최소 확인

저장소 루트에서 Node24 이상·Python3.12를 사용한다. 의존성 설치는 최초 또는 lock 변경 때만 한다.

```powershell
npm ci --ignore-scripts --prefix ops/public-host
npm --prefix ops/public-host run check
npm --prefix ops/public-host test
python -B -S scripts/estimate_public_host_cost.py ops/public-host/examples/cost-scenarios.json
node ops/public-host/publisher-cli.mjs --plan ops/public-host/examples/publish-plan.json
```

마지막 명령은 네트워크·토큰 없이 계획/바이트를 검사하는 dry-run이다.
기본 예제를 실제 전송 계획으로 바꾸지 않는다.
실제 배포 명령은 계정·도메인·권리·버전이 확정되기 전에는 여기서 만들어 실행하지 않는다.

로컬 리허설만 개별 실행하려면:

```powershell
node ops/public-host/rehearse-local.mjs
node ops/public-host/rehearse-lifecycle.mjs
```

이 두 명령은 합성 로컬 런타임을 만들고 종료한다. 검사/회귀에 이미 포함된 경우
바뀐 코드나 새로운 우려 없이 반복 실행할 필요는 없다.
작업 환경·관측량·수치와 한계는 [기록 폴더](results/ops/)의 해당 영수증으로 대조한다.

## 남은 작업 — 현재 우선순위 (2026-10-17)

사람 결정은 [WS-human1 결정서](WS_HUMAN_DECISIONS.md)에 모았다. 본인 Cloudflare·본인 시험·월 $10 이내 준비·이용 기록/피드백 OFF가 확정됐다.
본인 전용 합성 자원/배포/접속 경로는 WS-stage4에서 승인 후 완료했다. 이메일은 희망 채널이며 제공자/인증·실제 발송·공개/실경기 연결은 별도다. 개인 주소는 공개 기록에 넣지 않는다.
[지정 회신](https://github.com/Pitcheezy/transition-models/issues/18#issuecomment-6190443556)은 사용자 승인 후 1회 게시·원문 대조 완료했고 mail은 OPEN이다. [WS-stage1 비공개 준비안](WS_PRIVATE_STAGE_PLAN_20261015.md)과 [영수증](results/ops/ws_stage1_20261015.json)을 따른다.

WS-io1·WS-recovery2 뒤10/15 점검 당시에는 추가 독립 필수 작업을 찾지 못했다.10/17에는 위 두 운영 도구와 새 전달 준비를 별도 단위로 등록했다.
당시 점검은 결함 부재의 증명이 아니다. 아래 운영 결정·전달물·실기기 조건은 남으며, 반복 합성 검사를 실제 운영 완료로 바꾸지 않는다.

1. **실제 운영 결정 (WS-human1):** 본인 전용 합성 시험 승인·자원·배포는 WS-stage4 완료다. 이메일 제공자·인증·발송, 양쪽 긴급 안내 조작 권한/문구, 실제 경기·공개 범위 결정이 남는다. 연락 수단·응답 가능 시간은10/20까지다. 수집/피드백OFF를 유지하며 활성화 정책을 현 시험의 선행 조건으로 만들지 않는다.
2. **Song 후속 전달물 (WS-ops2 후속):** 미지원 예시·두 스키마 수정·업로더 후보를 로컬 준비했다는10/16 회신은 받았다. 비공개 전달 방법 확정 뒤 실제 소스/빌드·명시 SHA·규칙을 수신하고 검증해야 한다. 받은 첫 팩 검증을 반복하지 않는다.
3. **실제 서비스 연결 (WS-ops4):** 위 운영 결정과 Song 후속 전달물 준비 뒤 기존 시험 자원에서 Song 실제 발행기/화면·상시 감시/양쪽 알림·부하를 연결 검사한다. WS-stage4는 합성 전송/철회/복구 성공이며 실제 서비스 연결 성공이 아니다.
4. **실기기·실경기 확인:** Mac/Safari/iPhone, 공개 전후 표시, 피드 지연과 다음 투구 전에 추천이 나온 비율을 확인한다. 기존 I-device2 영상팩은 Mac에 비공개로 전송해야 한다. Windows/CI가 실제 기기를 대신하지 않는다.
5. **전체 출시 근거 정리 (WS-review2 잔여):** 과거 Codex 작성 묶음의 정확한 작성 모델 직접 근거가 아직 없다. 현재 수정분의 다른 모델 검토를 과거 전체 검토로 소급하지 않는다. 최종 양쪽 배포 버전·검사·권리/운영 승인 기록을 함께 고정한다.


**별도 연구/CV 후속:** CV-5a 시작 정의 결정, CV-6 독립 사람 검토, CV-7 미열람 영상/독립 라벨, 미트 전체 경기 처리량 측정이 남는다.
A-y/F-4i는 사용자 보류를 유지한다. 구형 모델 직접 이식(I-run1), C/D 연구 비교, KBO 확대를 공개 파일 서비스의 필수 선행 조건으로 추가하지 않는다.

## 운영자가 기억할 한계

- 구종 선택 비중은 사건확률이 아니다. 추천 효과나 투수 의도를 운영 기반이 증명하지 않는다.
- 여러 파일의 ETag는 같은 발행 묶음이나 투구 공개 시점을 보장하지 않는다.
- 네 기능 스위치를 꺼도 정적 화면은 남는다. 화면 전체를 안내로 바꾸는 것은 [안내 스위치](../ops/public-host/NOTICE.md)이며,
  둘 다 요청 비용을 자동 중단하지 않고 내려받은 자료를 회수하지 않는다.
- 제한기는 위치별 근사치이며 전역 비용 상한이 아니다. D1 당일 상한은 HTTP/읽기 과금 상한이 아니다.
- Windows workerd WSARecv64 종료 진단과 Windows WebKit의 credentials=omit 쿠키 전송 관찰은
  미해결 한계다. 실제 Safari/운영 로그 정책과 함께 확인해야 한다.
- 정상 종료 후 로컬 재시작 통과는 강제 종료/전원 손실·클라우드 백업 복원·생산 cron 성공이 아니다.

## 세션과 CI 규칙

1. 하루 한 번 양쪽 board/열린 mail을 읽는다. 착수 전 이슈에 합격 기준을 적고 우리 board/CHECKLIST를 선점한다.
2. 최신 main에서 짧은 작업 브랜치를 만든다. PR을 일찍 열고 해당 검사를 통과한 정확한 커밋만 병합한다.
   자동 CI는 PR과 main push이며, PR 없는 작업 브랜치/tag에는 자동 실행되지 않는다.
   필요하면 workflow_dispatch를 수동 실행한다. 실제 branch protection 강제 여부는 별도 확인이다.
3. 완료 댓글에 범위·검증·커밋·산출물/SHA·다음을 기록하고 자기 진행 줄만 반납한다.
   공개 이슈에는 비밀·접속 주소·개인정보를 넣지 않는다. 상대에게 발신/변경할 권한을 새로 추정하지 않는다.

[현재 협업 규약](COLLABORATION_PROTOCOL.md)과 [보존한 초기 운영 인계](history/WS_OPERATIONS_HANDOFF_20261012.md)를 구별한다.
운영 코드의 다른 모델 검토가 출시 조건이다. 기존 같은 Codex 검토로 소급 충족하지 않는다.
이 문서는 실제 파일 검증·출시 완료 기록을 대신하지 않는다.
