# WS-partner1 — Song 합성 연결 요청 수신과 준비

2026-10-17. 새 [COLLAB-001 후속 요청](https://github.com/Pitcheezy/transition-models/issues/18#issuecomment-6212003299)을 읽었다. **후속 소스·빌드는 아직 받지 않았으며, Song의 접속/실제 시험은 승인되지 않았다.** 이번 작업은 수신 사실과 실행 조건을 정리한 것으로 실제 연결 성공 기록이 아니다. [조회 영수증](results/ops/ws_partner1_20261017.json).

## 새로 확인한 것

- Song은 로컬 후보 `1f0260fa0d2da40b229507d5ca15f45d7c13593d`에 미지원 예제, probability/target 스키마 수정, 조건부 업로더, 401/503 화면 처리가 있다고 보고했다. 원격 공개·소스 수신·독립 검사는 확인하지 않았다.
- 소스 패치·public 빌드·명시 파일 SHA 목록·검증/한계 인계를 비공개로 전달할 준비가 됐다는 요청이다. 준비됐다는 보고와 실제 파일 도착을 구별한다.
- 원하는 시험은 한 미사용 경기 키, 합성 JSON 최대2KiB, 실패/읽기/정리까지 runner 총18요청·120초 이내다. 실경기·일반 공개·Cloudflare 계정/API 편집 권한을 요청하지 않았다.
- Song의10/16 상호조회는 [상황판 댓글](https://github.com/SongRoute/pitcheezy/issues/35#issuecomment-6210389223)에 근거가 있다. 10/17 일일조회는 별도 미확인이다.

## 기존 호스트로 가능한 것과 실제 제약

근거는 [WS-stage4 실제 기록](WS_STAGE4_CLOUD_TRIAL_20261016.md)과 [사람 승인 범위](WS_HUMAN_DECISIONS.md)다. 배포 소스는 `87168d7bc42f11f76886e475f919caff7674b60a`, WS-stage4 최종 설정은 gateON·자료읽기/업로드/수집/피드백OFF다. 이는10/16 확인 결과이며 오늘 실계정 재조회는 하지 않았다. 새 소스 병합이 실제 배포를 바꾸지 않는다.

- `gateway.mjs`의 `permittedKey()`는 `/v1/game/<양의 정수>.json` 경로를 허용한다. 업로드는 그 앞에 `/_publish`를 붙인다. 파일 종류/필드/명령을 새로 발명하지 않는다.
- `authorize()`는 `PUBLISH_TOKEN_SHA256` **하나**와 비교한다. 그 토큰은 허용된 모든 발행 경로에 적용되며, 특정 경기 키 한 개나 기간으로 강제 제한하지 않는다. 현재 구현을 키 범위 토큰·자동 만료 토큰이라고 설명하지 않는다.
- 회수는 운영자가 업로드OFF 및 digest 교체/삭제를 수행해야 한다. Cloudflare 편집 API 토큰의 만료와 발행 bearer의 만료는 서로 다르다.10/16 API 토큰의 확인된 만료 시각은 이미 지났으며 오늘 재사용하지 않는다.
- 관람 코드는 발행 bearer와 별도이며 세션은10/16 설정 기준3600초다.120초 runner 종료가 관람 세션 만료를 뜻하지 않는다. 코드 digest 회수로 관련 세션을 무효화하는 범위는 `access.mjs`/ACCESS.md와 실제 배포에서 확인한다.
- 60요청/60초 제한기는 위치별 근사치이며 전역18요청 한도나 청구 상한을 강제하지 않는다.18회/120초는 Song runner의 유한 실행 조건이다. 우리 운영자 검증 요청 수와 관리 API 호출도 별도로 기록한다.
- 정상 DELETE는 exact ETag의 삭제표식이다. 물리 삭제가 아니며, 사전 HEAD가200이면 기존 객체/표식 여부와 관계없이 새 키로 다시 협의하고 중단한다.

## 비공개 전달 제안 — 아직 확정 아님

새 공유 서비스/권한을 만들지 않고 기존 사람 간 비공개 전달로 ZIP을 받은 뒤, 우리 담당자가 현재 작업 채팅에 첨부하는 방법을 제안한다. 공개 GitHub 댓글에는 ZIP 링크·주소·토큰·개인 경로를 적지 않는다. 실제 전달 채널/수신 담당은 사람이 확정한다.

받을 묶음:
1. 기준 전체 커밋과 필요한 범위의 소스 패치 또는 소스 묶음. 포함 파일을 명시한다. 원문 fixture·영상·전체 디스크 목록·비밀은 제외한다.
2. public 빌드와 명시 파일 SHA-256, 빌드 명령·lock/도구 버전·환경 변수 이름. 빌드와 소스의 일치 근거를 포함한다.
3. `unsupported` 예제, 수정 스키마와 계약 버전, 순번/재시작/정정/health 규칙.
4. runner의 비활성 설정 예제, 한 키·2KiB·18회·120초의 검증 결과와 실패/unknown 시 처리, 정리/회수 담당 구분.
5. 알려진 한계와 절차 이탈 정정. 이력 보고를 독립 검증으로 바꾸지 않는다.

수신 뒤 먼저 ZIP 경로/크기/압축 구조와 명시 SHA를 검사하고 격리된 우리 임시 폴더에 푼다. 임의 설치 스크립트/시작 프로그램은 실행하지 않는다. 기존 릴리스 빌더와 설정 검사로 정확한 소스/빌드/호스트 버전을 묶는다. 상대 저장소를 checkout·편집·실행하지 않는다. 수신한 정적 파일 검사와 상대 서비스 운영은 구별한다.

## 실행 전 완료해야 하는 표

- **사람 승인:** 본인 단독에서 Song 합성 runner까지의 접속 확대, 시험 범위/창, 단일 writer 담당, 비공개 전달 방법, 제시한 고정 실행안.
- **우리 담당:** 현재 배포/원본 설정 보존, 유효한 최소 관리 권한, 제한된 새 시험 키의 HEAD404 확인, 시험용 발행/관람 자격 구분과 회수 절차, 시험 전후 네 토글과 gate/notice 확인.
- **Song 담당:** 전달팩 고정·runner 승인 설정, 본인 프로세스 실행/중단, 최대 횟수/시간/본문 제한과 단일 writer 준수, 소스/해시/결과 영수증.
- **중단 조건:** 키/표식 존재, 출처/SHA 불일치, 인증/토글 사전조건 불충족, 예상 밖 HTTP/본문/ETag, 초과예산 또는 unknown. 자동 재시도·ETag 새로 읽고 덮어쓰기·물리 삭제 금지.
- **종료:** 정상 조건부 삭제표식/후속 확인과 unknown 보존을 구분하고, 운영자가 읽기/업로드OFF·수집/피드백OFF·gateON으로 복귀, 시험 자격 회수/실제 거부 확인. 실패했으면 복구 미완료를 기록한다.

이 표는 자동 스케줄이나 상대 접속 승인이 아니다. 현재 호스트의 광범위 bearer 권한을 이해한 구체 승인 또는 더 좁게 격리한 실행안이 먼저 필요하다. 서버 권한을 한 키로 제한하는 기능을 새로 구현했다는 뜻이 아니다.
