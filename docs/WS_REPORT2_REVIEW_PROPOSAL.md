# WS-report2 보고서 연결 변경안 — 사용자 승인 수신

2026-10-15. 변경 대상은 **우리** `ops/public-host/report.mjs`와 해당 회귀 검사다.
기존 실행 중인 서버·공개 서비스·수집 설정·Song 저장소는 변경하지 않는다.

## 적용하려는 정확한 동작

1. 읽기 전용 SQLite 내보내기의 집계 검증은 기존 보고서 행 검증을 재사용한다.
2. 스냅샷에서 나온 집계에는 원본 SHA-256, UTC 날짜 단위, 수집·보존 범위 미확인 표기를 보존한다.
3. 해당 경기의 남아 있는 행이 없으면 `no_data`, 수치는 `null`로 표시한다. 실제 이용자 0명으로 쓰지 않는다.
4. 남아 있는 행이 있으면 `partial_data`로 합계를 보여 주되 전체 수집을 확인했다고 쓰지 않는다.
5. 일별 합계를 특정 경기의 몇 시~몇 시 수치로 표시하지 않는다. 날짜 전체 집계이며 수집 누락·삭제 여부가 미확인임을 본문과 미측정 목록에 적는다.
6. 꺼진 수집 채널은 기존처럼 미측정이다. 기존 스냅샷 표시 없는 입력의 동작은 유지한다.
7. 출처 SHA와 생성시각은 운영자용 JSON에 보존한다. 원본 DB 경로·세션 ID·개인정보는 결과에 넣지 않는다.

## 확인 방법

만료/빈 DB, 일부 날짜, 한 시간짜리 보고 기간, 채널 OFF, 잘못된 메타데이터, 기존 보고서 호환을 합성 자료로 검사한다.
최종 코드에는 다른 모델의 검토를 받는다. 실제 Cloudflare DB 조회·배포·발송은 별도이며 이번 변경에 포함하지 않는다.

## 승인 이력

보조 에이전트의 자동 승인 검토가 하트비트의 읽기 전용 조건을 이유로 수정을 거절했다.
이후 사용자 “다음 작업 이어서 진행하고 남은 작업 리스트업”과 선점 근거를 제시한 재심도
해당 파일 변경에 대한 명시적 재승인 부족으로 거절했다. 이 문서는 승인용 변경안이며 코드 적용·검사 완료 기록이 아니다.

2026-10-15 사용자가 “우리 보고서 파일 수정·검증 승인”을 명시했다. 승인 범위의 구현·검증을 재개한다. 구현 완료와는 구별한다.

승인 범위 구현 후 전체 Node209검사와 내보내기→보고서 파일 연결을 통과했다. 최종 고정 코드의 다른 모델 검토는 별도 진행한다.
