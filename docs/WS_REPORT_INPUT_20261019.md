## 실제 재현과 수정

- `2026-02-30T00:00:00Z` 입력이 수용되어 계산에는3월2일, 표시에는2월30일을 쓰던 것을 확인했다. UTC 달력 시각을 다시 변환해 원래 시각과 일치해야 수용한다. 정상 윤년·초 단위·소수1~3자리와 기존 연도 범위를 유지한다.
- 알림 최종 시각 `not-a-timestamp`가 필터에서 사라져 모의확인0건·이력보존complete로 출력되던 것을 확인했다. 소비하는 행 상태/시도 횟수/밀리초 정수와 제공된pending 배열을 검사한다. 잘못된 값은 `invalid_alert_state`로 거부한다.
- 전체 알림 상태 검증기를 강제로 적용하지 않는다. 보고서의 기존 최소v1/v2/v3 입력, 추가 필드, incidents 생략·pending 생략/null 호환은 유지한다. 보존범위complete는 전체 시도 원장 완전성이나 실제 이메일 전달을 뜻하지 않는다.
- CLI는 이 입력 검증을 출력 생성·잠금 전에 수행한다. 기존 데이터나 보고서를 오류 정정 명목으로 덮어쓰지 않는다.
