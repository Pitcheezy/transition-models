알림/보고서 계열 검사에서 매 실행마다 남던 테스트 폴더60개를 정리한다. 운영 코드·계약·이미 전달한 ZIP은 변경하지 않았다.
기준 `724888c`, 선점 `e89c615`. [사전 합격 기준](https://github.com/Pitcheezy/transition-models/issues/3#issuecomment-6262733183), [명령·파일 해시·검증 영수증](results/ops/ws_test_cleanup_20261019.json).

## 변경과 검증

- 네 테스트 파일의 임시폴더 생성을 테스트 전용 도우미로 모았다. 생성 직후 종료 훅을 등록하고, 정확한 경로·디렉터리 identity를 확인한 뒤 일반 파일만 제거한다.
- 새5검사: 자식 테스트 정상/준비 실패/판정 실패 뒤 정리, 링크 또는 교체된 root 거부. 인접 확인 파일을 보존했다.
- 관련70검사 두 번 통과(12.809/12.766초), 테스트 폴더 잔존0. 전체Node327통과(22.449초), 체크리스트8·문법·diff 검사 통과.
- 전체 실행의 검증 부모에는 npm의 `node-compile-cache`만 추가로 남았다. 정확히 이번에 만든 부모와 확인 파일을 검증 후 정리했다. 기존 임시폴더는 삭제하지 않았다.
- 처음 추가한 자식 실행 검사는 `NODE_TEST_CONTEXT` 상속으로3개 실패(기존65+경로보호2통과)했다. 자식 환경만 분리하고 실제1개 실행을 확인하도록 수정해 최종 통과했다. 과거 실패를 숨기지 않는다.
- 작성 Codex(GPT-6 계열, 정확한 세션 model id 미노출). 운영파일70개는 기준과 불변이다. 테스트 코드 추가 검토와 CI/병합 결과는 PR 및 board에 기록한다.

## 범위와 한계

강제 종료/전원 손실 시 정리는 보장하지 않는다. 이 도우미는 신뢰 가능한 단일 테스트의 평평한 임시폴더용이며, 예상하지 못한 항목·root 교체는 삭제를 거부한다. 실제 서비스 배포·이메일·공동 연결·Mac 검사는 수행하지 않았다.

함께 갱신한 [운영 인계](WS_OPERATIONS_HANDOFF.md)는 사용자 반환팩 전송·상대 정적 수신 확인, 승인 게시한 #38과 라벨 권한 한계, 아직 미합의인 공동 시험 원장을 구분한다. 새로운 상대 발신은 없다.
