# COLLAB-001 — v4.2 수신 검증과 한 키 시험 준비 회신 (미발신 초안)

형, v4.2 받았고 181,953bytes·SHA-256 `37c0d0715469952fadb796709dff91d5d86797b9e95d690cc03541466109693b` 일치 확인했어. 원본 ZIP·발행기 소스·화면은 비공개로 보관했고 공개하지 않았어. 우리 팩 검증 결과도 #18에서 확인했어.

**확인·반영한 것**
- 내부21파일 해시와 예제5개 스키마, 공개 빌드4개 핀 통과. 우리 로컬 gateway로 예제5개 원문 왕복도 확인했어.
- 경기파일 변경 시각으로 생존을 판단하지 않고 health 최상위 시각+명시한 진행 중 경기의 game_checks를 보도록 우리 감시를 보완했어. file_sequence<sequence_checked는 정상, 종료 경기는 대상에서 제외, 누락/철회는 미확인으로 남겨. 활성 경기 목록은 운영자가 갱신해야 해.
- held_last_accepted는 이미 수용 가능했고 원문 보존 회귀를 추가했어. 받아둔 투구가 보인다고 추천까지 있었다고 해석하지 않아.
- 받은 화면은 Windows Chromium의 별도 static mock에서15항목 통과. health만 새로우면 경기 재GET을 생략하고 file_sequence가 늘면 다시 받는 것도 확인했어. 원본시각 검사와 시각이동 파생본은 나눴고 원본은 그대로야.
- 제공 verify_offline은 Windows의 fcntl 부재로 실행 실패야. 등록된 WSL도 가상화 비활성으로 시작되지 않아 수정/우회하지 않았어. 무결성/스키마/전송/화면 검증과 실행기 검증을 구분했어. 이쪽에서 전체 발행기나 모델을 돌린 것은 아니야.

**추가 연결 준비**
- 받은 화면+우리 고정host의 비공개 후보 ZIP/설정과 자격 없는 dry-run을 통과했어. 실제Worker+화면을 같은 새 loopback에 붙인22항목(105요청)도 통과했어. 로그인·갱신·철회/복구·로그아웃을 봤지만, 여러키/큰예제의 로컬검사라 한 키 실제연결 검증과 구분해. 후보는 형 화면이 들어 있어 공개하지 않고, 실배포는 아직이야.

**맞출 사항에 대한 답**
- 전달 무결성은 원본 ZIP/파일 바이트 SHA가 기준이고, LF 정규화는 소스동치 보조 근거로만 남기자. 새 우리 자료는 Git blob LF로 포장할게.
- worker/gateway/access/notice/telemetry5파일은 PR42와 Git blob이 같아. runner pin48ec406은 유지하고 실제 배포버전은 따로 대조하자. 범위/만료 코드는 아직 실호스트에 올렸다고 확인하지 않았어.
- 남아 있는10/16 배포 설정에는 PUBLISH_LIMITER60회/60초이고 HEAD/PUT/DELETE가 publisher 키를 공유해. 현재 계정값은 시험 직전에 재확인할게. 한 키 scope는 합성 시험 전용이고 다중파일 실발행 범위/회수는 따로 정하자.

**한 키 시험 전에 결정할 것**
1. 시험 날짜·시간(KST), 중단 연락수단/서로 응답 가능한 시간.
2. 단일 writer는 형 맥미니의 이 runner 하나, 우리는 배포·키 발급·감시·회수 담당으로 제안. 실제 수행은 양쪽 확정 뒤.
3. 요청예산 조정: runner가17회라 로그인1+발행회수후HEAD1+관람세션회수GET1까지 최소20회야. notice 등 사전점검/진단·관리 API도 별도 원장에 합산해야 해. 첫/마지막 HEAD가 이미 키확인/정리확인을 하므로 중복하지 말자. 로그인 준비를 별도 승인·계수할지, 전체한도를 명시 변경하고 실패정리 예산도 마련할지 정해야 해. 현재18회/120초 조건은 유지해 둔 상태야. 주기감시/화면폴링도 본시험에 끼지 않게 하자.
4. 새 시험 자격과 관람세션을 비공개 전달하고 종료 전 삭제표식, 종료 뒤 업로드OFF·digest제거/교체·거부응답과 설정증거로 회수 확인. Song 전용 관람코드 digest도 제거하고 옛 세션 거부를 확인할게. 만료나 OFF503만으로 영구회수 완료라고 하지는 않을게.
