# 최종 발표용 로컬 시연·리허설 절차

2026-10-25 준비. 이 문서는 기존 자료를 이용한 **오프라인 저장 응답 시연**용이다. Song의 새 최종본, 공동시험, 실경기 연결과는 별개다. 학교 발표 시간, 실제 낭독 시간, 최종 발표 기기는 미확정이다.

## 지금 있는 것과 없는 것

- 있음: `web/pitch-studio/`의 현재 오프라인 패키지 생성 도구가 사용하는 31개 파일. 공식 첫 타석 영상 3개와 포스터, 저장 응답, 3구의 별도 정지 장면, 홈 화면의 4구 편집 영상이 포함된다.
- 있음: `docs/demo/intent_cv_summary_20261006.png`와 PPTX, 기존 대본, M3 보고서.
- 현재 작업트리의 명시된 경로에서 미발견: `outputs/demo_delivery/pitcheezy_offline_demo_20261006_v4.zip`과 압축 해제 폴더, `outputs/intent_label/delivery_20261005/intent_comparison_local/`의 원본 3개 파일(`index.html`, `manifest.json`, `README.txt`).
- 따라서 예전 v4 전체 패키지를 오늘 재검증했다고 말하지 않는다. `docs/demo/offline_start.html`은 패키지용 템플릿이므로 그 파일만 직접 열지 않는다. 비교 그림을 복원하기 전에는 전체 패키지를 생성하지 않는다.

## Windows에서 실행

우리 저장소 루트의 PowerShell에서 아래 두 검사를 차례로 실행한다. 기존 Python 환경과 Node가 필요하다. 첫 번째 검사는 사이트 파일·영상 해시·화면 동작 규칙을 검사하고, 두 번째는 저장된 39구 표시 자료와 고정 원본의 일치를 확인한다. 두 번째 명령에는 `--write`를 붙이지 않는다.

```powershell
& .\.venv\Scripts\python.exe scripts/check_pitch_studio.py
& .\.venv\Scripts\python.exe scripts/export_pitch_studio.py
```

검사가 통과하면 같은 저장소 루트에서 아래 로컬 서버를 실행한다. `8786`이 사용 중이면 기존 프로세스를 종료하지 말고 다른 빈 포트를 사용한다. 포트를 바꾸면 브라우저 주소의 포트도 함께 바꾼다.

```powershell
& .\.venv\Scripts\python.exe -m http.server 8786 --bind 127.0.0.1 --directory web/pitch-studio
```

브라우저에서 `http://127.0.0.1:8786/receiver.html?demo=849843-pa1`을 연다. 종료할 때는 이 작업으로 서버를 실행한 터미널에서 **Ctrl+C**를 누른다. 서버는 `web/pitch-studio/` 폴더만 제공하며 저장소 전체나 비공개 `outputs/` 폴더를 제공하지 않는다. 모델 실행, 다운로드, Cloudflare 설정 또는 요금제 변경은 필요 없다.

실제 발표 기기에서는 같은 절차를 별도로 확인한다. Windows 자동 검사나 macOS CI가 실제 Safari·아이폰 검사를 대신하지 않는다. Mac을 사용할 경우 최종 자료와 Python 환경부터 확인한다. 요약 장표는 서버 폴더 밖의 `docs/demo/intent_cv_summary_20261006.png`를 별도로 열어 둔다.

## 짧은 시연 동선

1. **범위 설명:** “저장된 추천 응답과 공식 투구 클립을 연결한 재생입니다.” 첫 타석 1구를 열고 Michael King 대 Pete Crow-Armstrong, 투구 키 `849843:1:1`을 확인한다.
2. **공개 전:** 결과가 숨겨져 있는지 확인하고 구종 선택 비중을 설명한다. 이를 스트라이크·안타 확률이라고 읽지 않는다.
3. **1구 재생:** **투구 영상 재생**을 누른다. 영상이 끝난 뒤 싱커·96.3mph·루킹 스트라이크가 표시되는지 확인한다.
4. **2구:** **다음 투구** 또는 **다음 투구 보기**를 누른다. 이전 결과가 사라지고, 영상 재생 후 스위퍼·86.4mph·헛스윙이 표시되는지 확인한다.
5. **3구:** 포심·97.6mph·삼진이 공개된 뒤에만 **미트 판독 장면**을 연다. 저장 원응답의 세부 결과는 파울팁(`foul_tip`)이며 화면의 결과 표기는 ‘삼진’이다. 초록 점은 별도 압축 영상의 3084번 정지 프레임에 저장된 미검토 AI 미트 중심이다. 공식 동영상의 추적점이 아니며, 저장된 미트 가로 위치와도 구분해 설명한다.
6. **평가 장표:** 별도 평가 2경기의 전체 86장, AI 출력 58장, 기권 28장을 설명한다. AI와 사람이 모두 표시한 58장의 미트 점 차이 중앙값은 2.5px다. 시연 경기와 평가 경기를 구분한다.
7. **종료:** 현재 완료 범위와 공동시험·실제 기기 확인·전시 부하 검증이 남았다는 점을 짧게 말한다.

1·2구에 미트 주석이 없는 것을 추가 기권 2건으로 세지 않는다. 별도의 39구 관측 자료에는 좌표 27개와 기권 12개가 있다. 제품 콘셉트 예시, 합성 수신 예제, 현재 클라우드의 합성 홈 화면, 실제 저장 응답 재생, Song의 최종 UI는 서로 다른 자료다.

영상의 일시정지·재개와 결과 숨김은 별도 기능이다. 결과를 공개 전 상태로 돌리려면 **결과 다시 숨기기**를 누른다. 영상 재생 막대를 앞쪽으로 옮기는 것만으로 결과가 숨겨진다고 가정하지 않는다. **이전 투구**·**다음 투구**로 이동하거나 결과를 다시 숨기면 이전 투구의 결과·미트 표시가 남지 않고 영상이 처음으로 돌아가는지 확인한다.

## 실패하면 바로 사용할 동선

- **영상이 열리지 않음:** **현재 투구 결과 공개**로 저장 결과를 보여 주고 영상 재생은 확인하지 못했다고 설명한다. 브라우저 보안 설정을 끄지 않는다.
- **화면 실행 실패:** 기존 CV 요약 PNG를 열고 아래 30초 목표 대체 원고를 읽는다. 비교 갤러리는 원본 복원 전에는 사용 가능한 자료로 표시하지 않는다.
- **인터넷 연결 실패:** 이 로컬 화면의 기본 시연은 네트워크 API에 의존하지 않는다. 공개 사이트로 전환해 복구하느라 발표 시간을 쓰지 않는다.
- **최종 서비스 장애:** 사람이 승인한 범위의 안내·연락 절차를 따른다. 발표 연습을 이유로 실제 서버의 설정이나 자격을 조작하지 않는다.

대체 원고의 실제 낭독 시간은 아직 측정하지 않았다.

> 현재 영상 재생에 문제가 있어 검증 결과로 설명하겠습니다. 미트 판독은 평가 2경기 86장 중 58장에 출력했고 28장에 기권했습니다. AI와 사람이 모두 점을 표시한 58장의 차이 중앙값은 2.5픽셀입니다. 실제 투수의 의도나 물리 정확도를 검증한 수치는 아닙니다. 서비스 측면에서는 자료 수신과 권한 회수 기반을 만들었고, 최종 공동 연결 검증을 남겨 두고 있습니다.

## 실제 기기 리허설 기록 양식

아래 결과는 미리 채우지 않는다. AI 브라우저 점검과 본인의 실제 기기·낭독 기록을 구분한다. 각 항목에 통과·실패·미확인 중 하나를 적고, 실패하면 투구 키와 재현 절차를 함께 기록한다.

- 일시 / 검사자 / 기기 / OS / 브라우저 / 소스 커밋:
- 1구의 초기 결과 숨김, 선수·투구 키 확인:
- 1~3구의 실제 재생과 종료 후 저장 결과 표시:
- 영상 일시정지·재개:
- 결과 다시 숨기기, 이전·다음 투구 이동 후 결과 제거와 영상 초기화:
- 3구의 별도 정지 장면, 영상 복귀·결과 숨김 후 미트 점 제거:
- 영상 실패 시 수동 결과 공개와 요약 PNG 전환:
- 좁은 화면에서 버튼·범례·글자의 가독성:
- 전체 낭독 시간(초, 실측):
- 실패 항목 / 투구 키 / 재현 절차 / 수정 후 재검사:
