# Pitcheezy 최종 발표 준비 원고

2026-10-25 작성. 근거 기준: 우리 main `4e6aba71487ffe0c2ce9dd6df658ca9db9da9953`(PR64 병합 포함).
이 문서는 검증된 내용으로 작성한 발표 초안이다. 발표일·학교 규격·제한 시간은 미확정이며, 최종 PPT/인쇄 포스터 완성이나 공개 발신을 뜻하지 않는다. 기존 M3 결과·JSONL·10/6 장표는 변경하지 않았다.

## 1. 발표의 중심과 역할

**Pitcheezy — 다음 공을 이해하는 야구 관전 서비스**

야구 기록에서 계산한 투구 선택과 실제 결과를 비교하고, 영상에서 읽은 포수 미트 위치를 보조 정보로 보여 준다. 현재 시연 가능한 첫 타석은 저장 응답과 공식 투구 클립의 재생이다. 최종 목표인 투구 전 실시간 분석과 구별한다.

조현준 담당 범위는 **미트 판독·검증, 설명용 화면과 저장 응답 연결, 호스팅·업로드 수신·접근 회수·운영 증거**다. 전이확률 모델 비교·오류 복구는 우리 레포의 선행 연구다. 현재 서비스의 목표·추천 모델·발행기·관전 화면은 Song 담당이다. 팀 전체 성과와 개인 담당 범위를 함께 설명한다.

코드 작성·검토에는 Codex와 Claude를 활용했다. 아래는 개인이 모든 코드를 직접 작성했다는 주장이 아니라 담당 범위에서 축적한 산출물과 검증 근거다. 모델 이름·작성자·검토자는 고정 작업 기록에서 확인한다.

## 2. 바로 읽을 발표 원고

아래 8장 구성은 편집용 초안이다. 짧은 발표에서는 5번 연구 이력을 부록으로 옮긴다. 소요 시간은 아직 측정하지 않았다.

### 1장 · 야구 팬의 질문

“좋은 결과가 나온 공이 항상 좋은 선택이었을까요? Pitcheezy는 다음 공의 선택과 실제 결과를 비교해 관전을 돕는 서비스입니다. 저희는 추천 모델, 영상에서 얻는 보조 정보, 이를 보여 주는 서비스를 나누어 만들었습니다.”

화면: 작품명과 ‘다음 공으로 무엇이 유리한가 / 실제 공은 어땠나’ 두 질문. 실투·타자 책임·감독 교체 오류를 판정한다고 쓰지 않는다.

### 2장 · 기록과 영상이 만나는 구조

“팀원의 모델과 발행기는 추천 결과를 파일로 제공합니다. 제 쪽에서는 그 파일을 받아 사용자가 읽도록 제공하고, 영상에서 읽은 미트 위치를 경기·타석·투구를 식별하는 투구 키로 연결합니다. 두 저장소는 공개 발행 파일과 업로드 API를 기준으로 만납니다.”

화면: 기록→Song 모델/발행기→공개 파일→우리 호스팅→관전 화면. 영상→우리 미트 판독→투구 키 연결은 별도 경로다. 실제 공동 연결 검증은 아직 완료 전이라고 표시한다.

### 3장 · 한 타석 시연

“2026년 9월 29일 컵스와 파드리스 경기의 첫 타석입니다. Michael King과 Pete Crow-Armstrong을 보여 줍니다. 먼저 추천 후보를 보고 영상을 재생하면 저장된 실제 결과가 공개됩니다. 구종 옆 비율은 구종 선택 비중이며, 안타나 스트라이크가 될 확률과는 다릅니다.”

화면: `receiver.html?demo=849843-pa1`. 1구 숨김→재생→결과, 3구 공개→‘미트 판독 장면’ 버튼으로 별도 정지 장면. 현재 관측과 최종 Song 화면을 혼용하지 않는다.

### 4장 · 미트 판독을 어떻게 확인했나

“미트가 보이지 않거나 판단하기 어려우면 값을 만들지 않고 기권했습니다. 평가 두 경기의 86장 중 AI는 58장에 점을 냈고 28장에 기권했습니다. AI와 사람이 모두 점을 낸 58장에서 차이의 중앙값은 약 2.5픽셀이었습니다. 이 수치는 같은 화면에서의 판독 차이입니다. 실제 공간의 정확도나 투수 의도까지 검증한 수치는 아닙니다.”

화면: 전체 86, 출력 58, 기권 28, 공동 표시 58의 중앙 2.53px / 90분위 6.51px. 작은 표본·사람 1명·압축 영상 조건을 같은 장표에 적는다. 시연 경기 849843과 평가 경기 849845 / 823407을 구별한다.

### 5장 · 성능 숫자를 믿기 위한 선행 연구

“초기 모델 비교에서 입력과 정답의 연결 오류를 발견해 투구 ID로 다시 맞췄습니다. 이후 투구 전에 이용할 정보만 쓰도록 평가 조건을 분리했습니다. 확률 예측은 기준선보다 개선됐지만, 그것만으로 더 좋은 투구 정책이라고 결론내리지 않았습니다. 실점 감소의 신뢰구간이 0을 포함해서 효과를 입증하지 못했다고 보고했습니다.”

화면: 우리 9/21 운영 연구 CE 1.287400→1.274251, 낮을수록 좋음. 정책 비용 차이 −0.0862 runs/100 decisions, 95% CI [−0.4046,+0.2304]. Song 현재 서비스 모델의 성능으로 표기하지 않는다.

### 6장 · 서비스는 멈추고 회수할 수 있어야 한다

“저는 호스팅과 업로드 수신, 관람 권한, 비상 안내와 검증 기록도 맡았습니다. 본인 시험에서 정상 접속 후 같은 세션의 권한을 회수해 차단되는 것을 확인했습니다. 발행 자격 회수도 서버 로그와 대조했습니다. 비상 안내 기능은 동작했지만 요청 한 건의 로그를 확보하지 못해 전체 증거는 미완료로 남겼습니다.”

화면: 관람 200→401 / 로그 4건, 발행 HEAD 404→401→503 / 로그 3건, 안내 기능 13건 / 로그 12건. 본인 합성 클라우드 시험으로 표시한다. 소스 커밋·서버 버전·파일 해시는 구분한다. 비밀값과 실제 관리 주소는 노출하지 않는다.

### 7장 · 현재 완료와 다음 검증

“현재는 미트 판독 평가, 저장 응답의 한 타석 재생, 제한된 호스팅 시험까지 근거가 있습니다. 팀원의 새 최종본 연결과 공동시험, 실제 발표 기기 확인은 남아 있습니다. 전시회 30~50명 동시접속과 비용 검토는 11월에 진행할 계획이며 아직 통과했다고 말하지 않습니다.”

화면: 완료 / 연결 검증 대기 / 11월 확인을 나란히 적는다. 퍼센트 완성도 대신 실제 완료 범위를 제시한다.

### 8장 · 내가 만든 부분

“제 기여는 영상에서 미트 관측을 만들고 사람 판독과 비교한 것, 서로 다른 자료를 같은 투구로 연결한 것, 그리고 연결 결과를 안전하게 제공하고 문제가 생기면 회수할 수 있는 기반을 만든 것입니다. 최종 발표에서는 어디까지 측정했고 무엇이 남았는지 화면과 근거로 보여 드리겠습니다.”

## 3. 포스터에 넣을 문안

### 소개
MLB 투구 기록의 추천 후보와 실제 결과를 비교하고, 영상에서 읽은 포수 미트 위치를 함께 살펴보는 관전 보조 서비스.

### 사용 흐름
1. 투구 전: 기록에 기반한 추천 후보를 확인한다.
2. 투구 공개 후: 실제 구종·위치·결과와 비교한다.
3. 관측이 있으면: 같은 투구의 미트 가로 위치를 보조 정보로 확인한다.

### 우리 검증 결과
- 미트 판독: 평가 2경기 86장, AI 출력 58 / 기권 28. 공동 표시 58장에서 차이 중앙2.53px, 90분위6.51px.
- 연결 시연: 제공받은 저장 응답과 공식 첫 타석 영상 3구를 투구 키/playId로 연결.
- 운영: 본인 시험에서 관람·발행 자격 회수와 서버 로그를 대조. 비상 안내 로그 1건은 미확인.

### 한계
미트 판독 차이는 물리 정확도·투수 의도 정확도가 아니다. 추천 비중은 사건확률이 아니다. 저장 응답 재생과 실경기 운영은 구별한다. 현재 공동시험·최종 발표 기기와 Mac/iPhone 리허설·전시 부하 검증은 남아 있다. 기존 Windows 사용자 확인은 별도 기록으로 보존한다.

### 최종 편집에 필요한 값
학교 포스터 규격, 발표일/시간, 저자·소속·지도교수 표기, Song이 확정한 최종 모델/정책 지표와 평가 조건, 사용 허용된 대표 화면, 공개할 QR 목적지. 원자료 없는97.8%·추천 속도 0.13초 등의 구형 수치를 채워 넣지 않는다. 추천 효과와 예측 품질을 별도 항목으로 표시한다.

## 4. 예상 질문과 답변

1. **미트가 투수의 의도인가요?** 현재 표시하는 것은 영상에서 보이는 미트 위치다. 투수 의도를 연구하기 위한 대리값 후보지만, 의도나 목표의 정답으로 검증하지 않았다.
2. **왜 높이는 표시하지 않나요?** 화면·보정·측정 평면의 불확실성을 감안해 합의된 가로 표시 범위로 제한했다. 높이 검증 완료 주장은 없다.
3. **1.1인치가 실제 정확도인가요?** 같은 변환을 적용한 AI·사람 x/z 좌표 거리의 중앙값이다. 물리 정확도나 가로 오차를 뜻하지 않는다.
4. **기권하면 성능이 좋아 보이지 않나요?** 그래서58개 조건부 거리와 전체86개 중 출력/기권을 함께 보고한다. AI 기권 28개 중 26개는 사람이 표시했으며 원인을 추가 검토한다.
5. **실시간인가요?** 현재 이 첫 타석은 저장 응답과 투구별 클립의 재생이다. 제한된 로컬 지연 측정은 했지만 실제 연속 중계의 처리 품질과 투구 전 발행 시점을 검증하지 못했다.
6. **스트라이크 확률도 나오나요?** 현재 받은 첫 타석 응답의 비율은 구종 선택 비중이다. 사건확률이 없는 응답에 예시 숫자를 넣지 않는다.
7. **추천이 더 좋은가요?** 확률을 잘 예측하는 것과 정책 효과는 다르다. 우리 9/21 정책 평가에서도 개선을 입증하지 못했다. Song 최종 평가는 고정 결과를 받은 뒤 별도로 인용한다.
8. **투수·타자·감독 잘못을 나눌 수 있나요?** 최종 지향점의 일부지만 현재 실제 경기에서 검증된 책임 판정 기능으로 발표하지 않는다.
9. **서버50명 가능한가요?** 기존 로컬 준비 결과는 있다. 실제 배포 환경의30~50명 시험과 비용 판단은11월에 진행하며 현재 미측정이다.
10. **AI가 코딩했는데 본인 역할은요?** 요구사항·역할·평가 범위를 정하고 자료 확인, 사람 라벨링, 계정 권한과 현장 동작을 담당했다. AI를 활용한 코드/검토 결과는 커밋과 실행 기록으로 관리했다. 직접 수행 이력이 없는 세부 구현을 손코딩했다고 설명하지 않는다.
11. **어느 쪽 코드를 수정하나요?** 자기 저장소만 수정하고 공개 파일 계약과 이슈로 협업한다. 상대 모델/발행기/관전 화면은 상대가 고친다.
12. **인터넷이나 영상이 실패하면요?** 로컬 저장 응답과 장표로 설명한다. 복구에 긴 시간을 쓰지 않고 실패한 시연 범위를 명시한다.

## 5. 지금 독립적으로 할 수 있는 일

- 이 원고의 수치·근거를 고정하고 발표 시간에 맞게 줄이기.
- 기존 로컬 시연의 준비물 확인, 결과 숨김/공개·전환·정지 장면 동선 확인.
- 최종 장표·포스터의 문안과 근거표 작성. 새 모델 수치는 대기 표시.
- 기기별 검사표, 예상 질문, 실패 시30초 설명과 자료 백업 목록 준비.

팀원 입력이 필요한 일은 새 고정 전달본·최종 모델 근거·공동시험이다. A-y 44구 사람 검토와 OCR확대는 보류를 유지한다. CV-6 별도 독립 26장 검토와 CV-7 새 영상 평가는 주장 범위를 넓히는 연구이며 파일 발행 서비스의 필수 선행 조건으로 추가하지 않는다.
