# D1 복구 절차의 합성 SQLite 연습 — WS-recovery1

현재 운영 데이터나 계정에 연결하지 않는 로컬 검증이다. [RUNBOOK](RUNBOOK.md)의 복구 후 점검을
새 임시 SQLite 파일로 연습한다. Cloudflare D1 Time Travel이나 R2 복구를 실행하는 도구가 아니다.
기존 [정상 종료 후 재시작 검사](LIFECYCLE.md)와 별개로 오래된 복구점의 위험을 확인한다.

## 실행

저장소 루트, 기존 Node 24 환경에서:

```sh
node ops/public-host/rehearse-d1-recovery.mjs
node --test ops/public-host/tests/d1-recovery.test.mjs
```

결과를 보관하려면 `--output <새 결과.json>`을 지정한다. 기존 출력은 덮어쓰지 않는다.
DB 경로·계정·접속 주소·스냅샷 입력은 받지 않으며 해당 인자는 실행 전에 거부한다.
Node 24.1의 SQLite 실험 기능 경고는 검증 실패와 구별한다.

## 실제로 확인하는 것

- 저장소 migration으로 세 테이블·네 인덱스를 생성한다. 정상 DB의 중복 ID 입력은 SQL이 거부한다.
- 합성 시각은 2026-10-15 12:00 UTC다. 닫힌 DB 파일을 백업·별도 복원 파일로 복사하고 바이트 SHA를 대조한다.
- 각 복원 파일을 읽기 전용으로 열고 실제 쓰기 거부, 검사 전후 SHA 불변을 확인한다.
- 10개 사례: 정상, 오래된 복구점, 만료 정리 후 복사본, 사고 전 budget 근거 없음,
  인덱스 누락, 같은 이름의 잘못된 인덱스, 스키마 변경, NULL ID, PK가 사라진 중복 ID,
  음수 budget. 스키마가 틀리면 행/집계 점검을 통과로 처리하지 않는다.
- 오래된 복구점에는 만료 세션·피드백이 각 1행 되살아난다. 유효 행 각 1개와 분리한다.
- 사고 전 합성 저장 횟수는 세션 5 / 피드백 3, 복구점은 2 / 1이다. 차이는 일일 상한 되감김으로 표시한다.
  사람 수나 피드백 품질의 측정값이 아니다.
- 기존 `cleanupTelemetry`를 SQLite 어댑터로 실행하면 만료 행은 사라지지만 budget 되감김은 남는다.
  이 연습에서 어댑터의 쿼리는 실제 SQLite에 실행하며 Cloudflare D1 런타임 호출로 부르지 않는다.
- 사고 전 budget 근거가 없으면 `missing_evidence`다. 현재 행 수로 과거 쓰기 횟수를 추정하지 않는다.
- 모든 결과의 `collection_resume_authorized=false`를 유지한다. 정상 검사는 수집 재개 승인이 아니다.

## 범위와 해석

`passed=true`는 위험 사례까지 예상대로 탐지한 **합성 연습 성공**이다. 모든 복원본이 정상이라는 뜻이 아니다.
검사기는 이 파일 내부의 정해진 합성 사례만 대상으로 하며 범용 운영 DB 검사기로 제공하지 않는다.
스키마는 현재 migration과 엄격히 대조한다. 의미가 같지만 SQL 표현이 다른 실제 복원본의 호환성은 미측정이다.

원본 합성 백업·사고 후 합성 DB는 점검 동안 보존되고, 종료 시 이번 실행이 만든 임시 폴더만 제거한다.
영수증에는 ID·접속 주소·개인 경로·비밀을 넣지 않는다. 소스 해시·실행 환경·사례별 진단만 남긴다.
실제 계정 복구, 전원 손실, R2 metadata/ETag 복구, 수집 자동 재개, 실제 RTO/RPO는 미검증이다.
이는 기존 WS-ops4e 복구 준비의 보완이며 별도의 출시 선행 조건을 추가하지 않는다.

검증 기록은 [WS-recovery1](../../docs/WS_D1_RECOVERY_20261015.md)을 따른다.
