# 시험 발행의 키·만료 제한 — WS-publish2

이 기능은 **우리 호스팅의 선택적 제한 장치**다. 공개 파일 v1의 필드, URL, 조건부 갱신 방식은 바꾸지 않는다.
실제 배포·팀원 접속 허용·비밀 전달·시험 시작 승인은 별도다. 기존 실자원에 자동 적용되지 않는다.

## 설정과 동작

- `PUBLISH_KEY_SCOPE`: 선행 `/` 없는 정확한 저장키 하나. 예: `v1/game/123.json`(합성 예시).
- `PUBLISH_EXPIRES_AT`: `YYYY-MM-DDTHH:mm:ss.sssZ`의 정확한 UTC 시각. 존재하는 날짜, 연도0001~9999만 허용한다.
- 둘 다 **없을 때만** 기존 범위로 동작한다. 하나만 있거나 빈 문자열/잘못된 값이면 발행을 거부한다. 빈 값을 기본값으로 추가하지 않는다.
- 범위는 기존 공개 키 허용목록 안에서 하나만 지정한다. prefix·목록·와일드카드·URL·인코딩 경로는 허용하지 않는다.
- `UPLOAD_ENABLED=true`, 올바른 `PUBLISH_TOKEN_SHA256` 인증, 기존 요청 제한·SHA·조건부 갱신도 모두 필요하다.
- 적용 대상은 `/_publish/...`의 PUT/DELETE/비공개 HEAD. 공개 GET/HEAD와 안내 스위치/관람 인증은 기존 규칙을 따른다.
- 설정 오류는503, 다른 키 또는 만료는403으로 거부한다. 응답에 키·시각·비밀 값을 반사하지 않는다.
- 서버 시각이 만료 시각 **이상**이면 거부한다. 비동기 제한 검사·본문 처리·해시 계산 뒤에도 저장 호출 직전에 다시 확인한다.

## 배포 후보 검사

`python -B -S scripts/check_public_host_config.py PATH_TO_CANDIDATE`

선택 필드가 있으면 검사기는 바이트 목록/해시 검사를 먼저 수행하고, runtime 다섯 파일
(worker/gateway/notice/access/telemetry)을 **신뢰한 현재 체크아웃**과 비교한다. CRLF→LF만
정규화하고 나머지 바이트는 같아야 한다. 옛 gateway가 새 설정을 조용히 무시하는 후보는 거부한다.
따라서 검사 도구도 검토된 고정 커밋에서 실행해야 한다. 다른 runtime 후보를 승인하려면 새 검토/검증이 필요하다.

이는 서명 인증이나 실제 배포 내용의 증명이 아니다. 원본 파일 SHA는 줄바꿈 정규화와 별도로 기록한다.
오프라인 검사는 시각의 형식만 확인한다. 실제 만료 여부는 요청 때 Worker가 판단하며 검사 결과는 계속 `deployable:false`다.

## 실제 공동 시험 전 조건

1. 받은 고정 소스/빌드/SHA와 시험 요청서를 대조한다. 전달물 수신과 접속 승인을 구별한다.
2. 사람 승인 후 미사용 시험키·종료 시각·단일 작성자·철회 담당을 비공개로 확정한다.
3. 새 제한을 포함한 검토된 host로 후보를 만들고 설정/로컬 runtime을 검사한다.
4. 실제 활성화는 승인된 배포 절차로 별도 수행한다. 기존 토큰은 재사용하지 말고 별도 시험 자격을 준비한다.
5. 종료 때 업로드를 끄고 발행 토큰 digest를 제거/교체한 다음 범위 설정을 정리한다. 실제 철회 여부를 확인한다.

**만료는 자격 자체의 영구 폐기가 아니다.** 두 설정을 지우거나 종료 시각을 연장하면서 같은 digest를 유지하면
이전 bearer가 다시 유효해질 수 있다. 만료 전에 이미 저장소에 전달한 요청을 취소하거나 저장 완료 시각까지 제한하는 보장도 없다.
만료 뒤 이 자격으로 정리 요청을 할 수 없으므로 정리 시각·소유자 복구 방법을 먼저 정해야 한다.

단일 키·만료만 제공한다. 팀원의 제안인 2KiB/총18요청/전체120초는 이 설정으로 강제되지 않으며
별도 시험 실행기의 예산으로 확인해야 한다. 기존 host의 본문 한도/limiter와 구별한다.
실제 다중지역 시계·CDN·Cloudflare 배포·공동 연결은 이 로컬 검사로 완료 처리하지 않는다.

검사: `node --test ops/public-host/tests/publish-scope.test.mjs` 및
`python -m pytest tests/test_public_host_config.py tests/test_public_host_release.py -q`.
결과와 고정 소스는 [검증 기록](../../docs/WS_PUBLISH_SCOPE_20261017.md)에 남긴다.
